# 实施计划

## 一、总体目标

实现需求工作空间、统一 Praxis 分支名和 Grill Me 调查门禁，并通过 MOM/AOTU backend 的
真实需求链路验证模板同步、知识库、Skill 与门禁证据。

## 二、范围说明

1. 新增 worktree binding ID 与兼容解析器。
2. 改为 `.worktrees/<REQ-ID>__<需求简称>/<REQ-ID>__<需求简称>__<repository_id>`，对 Agent 暴露需求根目录，
   对 Git/CodeGraph 暴露 `repository_path`。
3. 分支统一为 `praxis/<REQ-ID>__<需求简称>`，阶段只保留为 binding 元数据。
4. 调查策略新增必需 `grilling`，Agent 指引显示 Grill Me 需求确认。
5. 更新并运行用户本轮明确要求的聚焦 Praxis 需求测试；不运行 lint、类型检查、全量测试或质量复核。
6. 重装插件后通知执行 subagent 创建并保留 MOM/AOTU backend 工作树。

## 三、不在本次范围内的内容

- 不修改 MOM/AOTU 业务代码。
- 不删除或整理现有工作树。
- 不运行业务项目测试或质量复核。
- 不自动合并或推送 MOM/AOTU 的验证分支。

## 四、阶段划分

1. 完成需求、路径、分支与 Skill 调查证据。
2. 在 Praxis 隔离工作树修改 binding、命名和路由策略。
3. 静态检查、提交、合并、推送并重装插件。
4. subagent 用新版插件创建两个 backend 工作树并回传证据。
5. 汇总执行情况和后续优化方案。

## 七、第二轮优化（2026-07-21）

1. 将 CodeGraph 初始化纳入 `worktree create` 的成功不变量；初始化失败时保留工作树现场，
   binding 标记为 blocked，禁止返回完全 active。
2. `codegraph status` 支持 binding 或仓库工作树路径，并在结果中返回绑定信息。
3. 重复创建已有 binding 时执行 CodeGraph 自愈，不重复创建 Git 工作树。
4. Skill gate 无论通过或失败均写审计并返回 `audit_id`。
5. `--stage` 改为可选，缺省为内部元数据 `development`。
6. 业务 Skill 按 `project_id` 精确过滤；Java 编码规范同时要求 Java 仓库和代码修改意图。
7. 需求状态投影保留已有 `执行进度.md`；Praxis 已绑定工作树显示 `bound_active`，同时保留
   Worktrunk 原始状态供诊断。
8. 发布新版后依次重跑 MOM 和 AOTU 已保留验证需求；新门禁失败时立即停止并记录原始证据。

## 八、第三轮优化（2026-07-21）

1. CodeGraph init/sync 开始前写持久操作记录，默认执行器定期刷新心跳；成功、失败和可捕获
   中断均写完成状态与审计。
2. 对遗留 `running` / `interrupted` 操作做重入判断：心跳新鲜或 CodeGraph lock 存在时
   返回 busy，避免并发 sync。
3. 对无 lock 的既有索引调用 `codegraph status --json`；仅当项目路径匹配、索引 complete、
   pending changes 为零且无 worktree mismatch 时收养索引并生成 Praxis freshness 元数据。
4. worktree binding 记录初始化尝试次数和起止时间；busy 保持 `initializing`，只有确定失败
   才标记 `blocked`，收养成功后转为 `active`。
5. 先用聚焦单元测试覆盖“完成索引收养”“活动操作 busy”“操作状态收口”“binding busy
   不误阻塞”，再运行本轮受影响回归。
6. 发布重装后先重跑 MOM 的同一 create 命令；成功后才运行 AOTU，任一新缺陷继续 fail-fast。

## 九、第四轮优化（2026-07-21）

1. route 缺失时 `SkillInvocationService.gate` 必须返回 `SKILL_ROUTE_NOT_FOUND`，同时写
   `skill.gate` 失败审计并返回 `audit_id`。
2. `_gate_current_skill_route` 改为 fail-closed：需求不存在返回明确错误，route 不存在交由
   gate 统一处理，不得继续状态流转。
3. `worktree.create` 在任何模板同步或 Git 写入前执行需求当前节点 gate；失败时不创建 binding、
   工作树或分支。
4. `worktree.remove` 成功后核对绑定仓库中的真实分支；外部结果与 Git 不一致时清理已失效
   binding、写失败审计并返回可诊断错误，不声称完全删除。需求工作空间为空时安全移除空目录。
5. 先补四条关键路径失败测试：无 route 状态流转阻断、无 route gate 审计、无 ready gate
   工作树阻断、删除分支结果失真；再运行受影响模块回归。
6. 发布后新建 MOM/AOTU 验证需求，从 captured 节点开始验证 route → invoke → complete →
   gate → transition 的真实审计顺序；只有确认改代码的验证步骤才创建工作树。

## 十、第五轮本地运行文件准备（2026-07-21）

1. `Project` 增加 `local_files` 元组配置，加载时拒绝绝对路径、空段、`.`、`..`、反斜杠、
   Windows drive 路径和重复项；workspace 重写时保留该字段。
2. binding 激活和 CodeGraph 初始化前，从 `project.path` 主仓库按相同相对路径复制白名单文件；
   已存在目标不覆盖，审计只保存路径和状态，不读取或输出内容。
3. 任一源缺失、非文件、resolve 越界、目标为目录/不安全链接或复制失败时，将 binding 标为
   blocked，写 `worktree.local_files_failed` 并返回可重试错误。
4. MOM 与 AOTU 的 `web` 项目登记 `apps/web-antd/.env.development`；从 MOM 主仓库补齐当前
   `REQ-20260721-003` Web 工作树，保留其现有业务改动。
5. 更新 Praxis 工作流 Skill、AGENTS 管理区块和 README。测试执行等待用户明确批准；本轮只做
   配置解析、安全路径和实际文件存在性门禁。

## 十一、第六轮前端依赖准备（2026-07-21）

1. `Project` 增加 `worktree_setup_commands`，工作空间读写与 `workspace add` 保留显式命令；
   拒绝空命令、解析失败和重复项。
2. binding 激活时在 `local_files` 之后、CodeGraph 之前按 argv 顺序执行；不使用 shell，失败
   标记 blocked 并写独立审计，结果不携带命令输出和环境。
3. 用配置指纹跳过相同配置、已成功 active binding 的重复准备；blocked 重试和配置变化重新执行。
   `verifying` 需求只允许重入已有 binding，不允许首次创建。
4. MOM/AOTU 所有带 pnpm 锁文件的前端仓库配置
   `pnpm install --offline --frozen-lockfile`，不配置联网回退命令。
5. 刷新插件后通过 Praxis 重新激活当前 MOM Web binding，确认依赖目录生成且既有业务改动未变化；
   不运行测试、lint、类型检查或质量复核。

## 十二、第七轮 Fork 可见命名（2026-07-21）

1. 生成并持久化 `workspace_name`、`worktree_display_name`、`branch_name`、`display_slug` 和
   `short_name_snapshot`；同一需求后续仓库复用 `worktree_group`，阶段不参与命名。
2. 新建路径固定为 `.worktrees/<REQ-ID>__<简称>/<REQ-ID>__<简称>__<repository_id>`，分支固定为
   `praxis/<REQ-ID>__<简称>`；创建前同时校验 ID、简称、仓库后缀和 Git ref 合法性。
3. 已有 binding 名称不符时，create 返回 `WORKTREE_NAME_MIGRATION_REQUIRED`，不得静默沿用旧名。
4. 新增 `praxis worktree migrate-name <REQ-ID> --repository <id>`：预检目标冲突，移动 Git
   worktree，重命名当前分支，更新 binding 与受影响产出物路径，重建新路径 CodeGraph。
5. 任一步失败恢复旧 CodeGraph、分支、路径、产出物和 binding；补偿不完整时标记 blocked，
   保留诊断与审计。成功确认后才删除旧 CodeGraph 备份和空旧目录。
6. 更新 Praxis Skill、AGENTS 管理区块与 README；测试和质量复核继续等待用户明确批准。

## 五、阶段依赖

命名实现与插件重装完成后，才能执行 MOM/AOTU 的工作树创建阶段，避免生成旧结构。

## 六、风险与回退方案

保留旧 branch-key binding 的只读兼容解析；若新建失败，停止在 ready 状态，不回退到旧命名
继续创建，也不在业务仓库根目录修改代码。
