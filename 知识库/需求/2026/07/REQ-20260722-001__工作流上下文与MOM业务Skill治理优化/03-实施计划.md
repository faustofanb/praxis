# 实施计划

## 一、总体目标

让需求的当前约束、实施/验证状态和授权矩阵成为可审计事实；让每个项目在进入隔离开发或启动 Agent 时自动获得并实际消费最新上下文，且数据库连接事实不可因画像或预算缺失而丢失。

## 二、范围说明

- 业务 Skill 支持 project+intent 精准匹配，项目基础 Skill 保持自动加载。
- 外部 Skill 发现增加 SkillDock 标准目录。
- context 增加 P0 项目/数据库事实、intent 输入、项目隔离缓存键和紧凑关键事实投影。
- worktree ensure 自动为成功项目构建 coder context，并返回 bundle。
- agent start 可省略 context，自动按 binding 生成；handoff 与启动提示要求读取。
- Agent guidance、需求工作流 Skill 和 DBX Skill 同步更新。
- 新增可覆盖旧结论的结构化需求约束，并生成只读的当前约束与决策历史投影。
- 新增交付维度：实施状态、验证状态、人工验收状态，以及显式的 verification decline receipt。
- 计划阶段固定记录精确验证矩阵，后续节点从 P0 上下文复用。
- 产出物增加 `code-change` 类型，允许登记仓库、分支、diff 统计和文件哈希。

## 三、不在本次范围内的内容

不增加 `context consume` 收据，不实现跨会话向量记忆，不自动选择多个 DBX 连接中的某一个，不执行数据库查询，不改变数据库写入授权策略。不重写已有线性工作流节点；交付维度作为正交状态附加到现有生命周期。不将 MOM 报工细则写入 Praxis 通用代码。

## 四、阶段划分

1. 需求事实：实现约束卡、`supersedes` 历史和只读投影。
2. 交付语义：实施/验证/人工验收分维度记录，增加计划阶段验证矩阵和 decline receipt。
3. 路由：为业务专项 Skill 增加 project+intent 过滤并发现 SkillDock。
4. 编译：把项目、数据库、有效约束和验证矩阵作为 P0 注入，修正缓存身份并返回 critical facts。
5. 消费：worktree ensure 和 agent start 自动构建，render/launch 明确传递读取指令。
6. 指导与产出物：更新 CLI、Agent guidance、Praxis workflow Skill、DBX Skill 和 `code-change` 登记。
7. MOM Skill：在 `REQ-20260722-003` 中更新基础 Skill 并新增接口契约、报工闭环专项 Skill。
8. 验证：仅执行用户后续明确批准的聚焦 pytest 与 Ruff 范围。

## 五、阶段依赖

约束和授权投影先稳定，context 才能注入权威事实；context 编译接口先稳定，worktree 和 Agent 才能复用；业务 Skill intent 必须传入 context build，避免自动 bundle 继续加载无关专项 Skill。Praxis 路由修正后再安装 MOM 专项 Skill，确保它们只在命中 intent 时生效。显式 context ID 和显式 `context build` 保持兼容。

## 六、风险与回退方案

每个阶段使用行为测试锁定兼容性。自动 context 构建失败时保留已创建工作树并返回诊断；新增约束/交付数据使用可删除的 runtime state，无 schema 回填。工作树 preview/ensure 人工确认保持现有行为，只增加回归测试。
