# 调查分析

## 1、需求目标

修正规划模式数据库调查边界：项目画像中已登记的生产 DBX 连接应允许执行有明确目的、
只读、非持久化的调查。

## 2、业务背景

当前 Agent 指引和运行时代码把“生产连接禁止写入”错误扩大成“规划模式禁止查询生产连接”，
导致无法在规划阶段核对生产环境的实际结构和数据口径。

## 3、当前实现

- `DatabaseService.investigate()` 在 SQL 只读检查之前直接返回
  `DATABASE_PRODUCTION_INVESTIGATION_BLOCKED`。
- `praxis-requirement-workflow`、`dbx-database-investigation` 和 Agent guidance 均声明
  规划模式只能查询非生产连接。
- `DatabaseService.query()` 已独立保留生产写入禁止规则。

## 4、涉及业务域

plugin-development、数据库调查治理。

## 5、涉及系统和仓库

单仓库 `praxis-next`。

## 6、涉及模块

- `src/praxis/database/service.py`
- `src/praxis/agents/guidance.py`
- 数据库调查与需求工作流 Skill 文档
- 数据库服务和 Agent guidance 聚焦测试

## 7、业务规则

1. 连接必须已登记在项目画像中。
2. 规划调查必须有非空目的，只接受 SQL 安全检查判定为 read 的语句。
3. 显式数据库引用必须通过 `select current_database()` 核验。
4. 返回 `persisted: false`，不得登记为正式调查证据。
5. 生产写入、锁定读取、连接变更和默认库猜测继续禁止。

## 8、数据口径

不改变数据，仅放开满足现有只读门禁的生产连接调查。

## 9、接口与数据流

CLI `praxis database investigate` → application operation → `DatabaseService.investigate()` →
DBX identity check → read-only query。

## 10、现有能力复用

复用连接登记校验、`inspect_sql()`、DBX 显式引用解析、当前数据库核验和非持久化 receipt。

## 12、数据库调查

本次修复不连接任何数据库；通过 FakeDbx 聚焦测试验证治理行为。

## 13、影响范围

公共 CLI 行为、Agent 规划指引、两个数据库相关 Skill。普通查询接口的生产写入门禁不变。

## 14、风险分析

主要风险是误放开非只读 SQL或未登记连接。通过保留并回归验证现有 SQL 分类、连接登记、
目标库核验和生产写入测试控制风险。

## 15、待确认事项

无。用户已明确确认规划模式允许查询生产连接。

## 16、调查证据

- 用户纠正：规划模式允许查询生产连接。
- 文本检索定位到运行时生产调查阻断和三处对外规则表述。
- 聚焦测试 `test_plan_investigation_blocks_production_and_write_sql` 固化了错误行为。
- TDD RED：修改正确期望后得到 2 failed、18 passed，失败分别来自生产调查阻断和旧 guidance。
- TDD GREEN：最小实现后得到 20 passed。

## 17、分析结论

采用最小修复：删除 `investigate()` 中仅针对生产连接的拒绝分支，保持其余只读安全门禁；
同步修正外部指引和回归测试。
