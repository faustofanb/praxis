# 验收结论

## 1、验收范围

快速工作树、异步 CodeGraph、延迟 setup、需求回退、产出物 upsert、Skill 批处理、批准收据、执行预算、Agent 交接与耗时审计；并在 MOM/AOTU backend 做真实回归。

## 2、功能验收

- preview/ensure 的需求 ID + 简称命名通过。
- 本地模板分支同步发布分支后创建需求分支通过。
- binding active 与 CodeGraph 后台状态解耦通过。
- Skill 路由、调用、完成和 gate 均有独立 audit ID；业务 Skill 实际调用通过。
- 空调查/计划文档能阻止 ready，补齐知识后可继续，知识门禁通过。

## 3、异常场景验收

- 非法节点不再静默退化，常用英文阶段别名会规范化。
- Worktrunk 未实际删除分支时，Praxis 以 Git ref 为准并精确兜底删除。
- 删除绑定工作树前会取消其 CodeGraph 进程组。

## 4、数据校验

MOM 与 AOTU 的本地模板分支均包含各自发布分支，需求分支基线 SHA 与同步后的本地分支一致。

## 5、构建结果

未构建业务项目；本次回归不修改业务代码，也不安装 Maven 依赖。

## 6、测试结果

181 项 Python 测试、2 项 Node 测试全部通过。聚焦回归 101 项通过。

## 7、类型与代码质量检查

ruff 与 ty 全部通过。依赖审计在代码修改前通过；最终复跑因 PyPI 代理断开未完成，依赖文件未变化。

## 8、影响范围复核

业务项目仅保留需求知识文档和 Praxis 审计；测试工作树、测试分支和后台进程已清理。未触碰其他已有工作树。

## 9、性能验证

- MOM backend ensure：4377.543ms。
- AOTU backend ensure：3191.115ms。
- 单次 Skill complete-node：约 18–50ms。
- 旧全量 worktree status：MOM 10797.236ms、AOTU 9958.344ms；已新增按 binding 的单仓精确查询。

## 10、遗留问题

- Codex 插件安装不提供全局 `praxis` shell 命令；源码开发模式需显式 `--root`，可后续增加 CLI 安装入口提示。
- 覆盖率原始值 84.76%，项目整数精度按 85% 通过；建议后续将 coverage precision 配置显式化，避免日志歧义。
- PyPI 代理恢复后可再次执行 `mise run audit`，但不阻塞本次无依赖变更的代码交付。

## 11、最终结论

核心工作流与两项目真实回归通过，可以提交交付；网络审计复跑作为已披露的外部环境限制保留。
