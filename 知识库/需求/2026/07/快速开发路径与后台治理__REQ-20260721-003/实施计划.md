# 实施计划

## 一、总体目标

在不降低 Praxis 安全、审计和需求可追溯性的前提下，让多仓需求在 Git 隔离完成后立即可编码，重型图谱和依赖治理按需异步执行，并减少重复命令往返。

## 二、范围说明

- P0：`worktree ensure`、CodeGraph 异步化、`requirement reopen`、artifact upsert。
- P1：延迟 setup/preflight、migrate-name 自动 active、Skill 节点批处理与路由缓存。
- P1：范围化批准收据、证据/恢复/重试预算、Agent 精简交接和父节点回执。
- P1：统一耗时审计、AGENTS.md/CLAUDE.md 管理区块与使用文档。

## 三、不在本次范围内的内容

- 不引入 Redis、Celery 或远程任务系统。
- 不自动联网安装依赖、Skill 或 CodeGraph。
- 不将用户未明确批准的质量复核、lint、类型检查或测试纳入后台任务。
- 不改变业务仓库的发布策略。

## 四、阶段划分

### 阶段 A：快速工作树核心

1. 实现稳定命名 preview 及 preview_id，ensure 必须使用未过期快照。
2. 实现多仓 ensure 并行调度，各仓结果独立返回。
3. 拆分 active、preflight、prepare 和 CodeGraph 状态；默认 deferred setup。
4. 调整 migrate-name：Git/绑定/产出物迁移成功后直接 active，CodeGraph 后台重建。

### 阶段 B：CodeGraph 后台治理

1. 新增可通过 `python -m` 启动的 worker，传递 root/project/repository/binding。
2. 持久化 queued/running/completed/failed，记录 PID、heartbeat、耗时和日志路径。
3. 新增 `codegraph wait`/`run-pending`，语义查询可显式等待，普通调查优先 `rg`。
4. 有安全条件时尝试复用同 revision 快照；索引绑定绝对路径不可验证时放弃复制并转后台重建。

### 阶段 C：需求、产出物与 Skill 编排

1. 新增 `requirement reopen --reason`、独立审计和知识投影。
2. 实现 artifact 稳定键 upsert，区分 registered/refreshed 事件。
3. 实现 `skill complete-node`，一次提交已使用 Skill 及 outcome，仍写每个 Skill 的独立审计。
4. 实现路由指纹缓存，相同需求+节点+输入+库存哈希直接复用。

### 阶段 D：批准、预算、Agent 与可观测性

1. 新增需求范围化批准收据，后续门禁只匹配明确命令/验证矩阵。
2. 新增每阶段 evidence/recovery/retry 计数与默认上限。
3. Agent 交接输出精简包、`fork_turns=none` 建议、父节点单写契约和子 Agent 回执。
4. 为核心操作写入 `operation.timed` 审计，并在 CLI 返回 duration_ms。
5. 更新 Agent 管理区块、Skill 和 README，保留自定义内容。

### 阶段 E：验证与回归

1. 静态检查 CLI 映射、导入、文档与差异。
2. 仅在用户对本轮明确批准后，执行指定的 lint/typecheck/测试矩阵和 MOM/AOTU 真实回归。
3. 记录准备阶段耗时、后台状态和任何剩余缺陷。

## 五、阶段依赖

- A 为 B 提供 active 与后台状态边界。
- B/C 可独立开发，D 依赖 C 的批处理和审计模型。
- E 依赖 A–D 的代码稳定，且受用户验证批准边界约束。

## 六、风险与回退方案

- 保留单仓 `worktree create`，新 ensure 可独立回退而不破坏现有命令。
- 后台 worker 无法启动时，binding 仍 active，CodeGraph 标记 failed/queued 并允许显式 `run-pending`。
- 并行 ensure 部分失败时不自动删除已成功工作树，避免破坏可恢复状态。
- 数据结构优先使用 runtime_state 的可选字段，减少 SQLite schema 迁移风险。
- 如果后台图谱影响稳定性，可通过项目配置临时恢复 synchronous，但不默认回退。
