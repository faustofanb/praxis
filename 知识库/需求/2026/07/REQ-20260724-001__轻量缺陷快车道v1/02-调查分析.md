# 调查分析

## 1、需求目标

为单仓、至多三个业务文件且不触及数据库、权限、API 契约、事务或并发的低风险缺陷提供
`praxis fast start|confirm|red|status|finish`，把现有治理能力压缩为一次确认和可审计的
RED/GREEN、差异及增量类型验证。

## 2、业务背景

现有 Praxis 已具备需求投影、Worktrunk 工作树、范围化 approval receipt、节点 Skill 批处理、
执行预算和产出物登记，但 Agent 仍需逐项编排，且全量类型检查会重复证明模板分支已有错误。

## 3、当前实现

- CLI 由 `src/praxis/cli/__init__.py` 解析并映射到 `PraxisApplication`。
- `RequirementService`、`WorktreeService`、`ApprovalService`、`ArtifactService` 和
  `SkillInvocationService` 已提供快车道所需原子能力。
- `runtime_state` 可保存无迁移的扩展状态；当前没有 fast lane 或类型诊断基线。
- `ProcessRunner` 已提供 argv 执行、耗时、脱敏原始日志和 RTK 输出处理。

## 4、涉及业务域

`plugin-development`。

## 5、涉及系统和仓库

系统与仓库均为 `praxis-next`，单仓 Python 插件。

## 6、涉及模块

CLI/Application 分发、需求与工作树编排、批准与命令执行、Skill 路由、诊断基线、Agent guidance
和 bundled Skill 资产。

## 7、业务规则

- 快车道只接受一个项目、1–3 个规范且已跟踪的业务文件。
- 高风险或越界只降级，不删除需求、工作树或用户改动。
- 一次确认精确批准聚焦测试、`git diff --check` 和一个配置中的类型检查命令。
- 必须由独立 RED 凭证证明测试在业务实现前失败。
- finish 只登记 implemented，不提交、推送或伪装完整验证已通过。

## 8、数据口径

- fast lane 状态：candidate、confirmed、red_recorded、implemented、downgraded。
- 时间预算：定位 300 秒、实现 600 秒、治理累计 120 秒，均为软预算。
- 诊断集合按“相对路径、错误码、规范化消息”计数，忽略行列变化。
- 类型结果：passed、incremental_passed_baseline_failed、failed_new_diagnostics、
  baseline_unavailable。

## 9、接口与数据流

`fast start` 登记需求并生成 preview → `fast confirm` 完成轻量调查计划、创建工作树、保存批准和
基线 → `fast red` 保存预期失败 → 业务实现 → `fast finish` 校验范围并执行 GREEN、diff-check、
增量类型检查、产出物与 implementation 登记。`fast status` 全程只读查询。

## 10、现有能力复用

复用现有 StateStore、RequirementService、WorktreeService、ContextCompiler、ApprovalService、
ProcessRunner、ArtifactService、NodeSkillRouter 和 SkillInvocationService；不新增依赖或数据库表。

## 11、代码图谱调查

本需求涉及公共 CLI 和跨模块状态流。隔离工作树创建后，首次编辑前必须以 binding
`WT-REQ-20260724-001--praxis-next` 强制刷新 CodeGraph，并保存入口到 Application、需求、
工作树、批准、路由和产出物服务的调用路径及 Blast Radius。

## 12、数据库调查

不涉及业务数据库。Praxis 本地 SQLite 仅复用通用 `runtime_state`，无需 schema migration。

## 13、影响范围

新增 fast lane package 和 CLI/Application operation；扩展 Skill 路由请求 profile 与输出
execution principles；增加 Vitest ESM 模板。既有标准 CLI、MCP 和标准 Skill profile 保持兼容。

## 14、风险分析

- 编排中途失败可能留下已登记需求或已创建工作树：以阶段状态和幂等 confirm 恢复，不做破坏性补偿。
- 类型输出格式多样：只接受已识别诊断；无法判定时返回 baseline_unavailable。
- 低风险识别误判：采用保守降级且 v1 不提供覆盖参数。
- RTK 不可用：明确失败，不静默直跑。

## 15、待确认事项

无。用户已确认完整 v1、分组式 CLI、一次授权三项验证、懒生成基线、Vitest + ESM 模板、
可信 RED 和软预算语义。

## 16、调查证据

- `src/praxis/application.py` 已集中调度 requirement/worktree/approval/artifact/skill 服务。
- `src/praxis/governance/service.py` 支持需求范围化精确收据。
- `src/praxis/skills/routing.py` 路由指纹已包含 request，可安全加入 profile。
- `src/praxis/storage/sqlite.py` 的通用 runtime_state 支持新状态而无需迁移。
- 既有 `tests/test_interfaces.py`、`tests/test_skill_node_routing.py` 和工作树测试可作为兼容基线。

## 17、分析结论

采用专用 `FastLaneService` 加诊断基线组件的最小实现：Application 负责组合既有工作树上下文
编排，服务负责状态、资格、文档、命令证据和交付。标准流程不改语义，fast profile 仅缩减
可审计方法 Skill。
