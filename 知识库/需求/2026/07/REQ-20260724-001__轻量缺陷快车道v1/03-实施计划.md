# 实施计划

## 一、总体目标

交付完整轻量缺陷快车道 v1，使低风险小缺陷通过一次确认完成隔离开发授权，并以可信 TDD 与
基线增量类型检查交付 implementation。

## 二、范围说明

- 新增 `praxis fast start|confirm|red|status|finish` 和内部 `fast.*` operations。
- 新增 FastLaneService、诊断规范化与基线缓存。
- 新增 `fast-defect-v1` Skill profile 与 execution principles。
- 增加幂等轻量文档 managed block、Agent guidance 和 Vitest + ESM 纯函数模板。
- 增加聚焦单元与接口兼容测试。

## 三、不在本次范围内的内容

MCP 新工具、后台定时器、自动提交/推送、全量构建/测试、Ruff、ty、代码审查、发布安装和对
高风险任务的快车道覆盖开关。

## 四、阶段划分

1. 在隔离工作树取得 CodeGraph 入口、调用路径和 Blast Radius。
2. TDD 实现 FastLaneRecord、资格和预算状态。
3. TDD 实现诊断规范化、基线指纹与增量比较。
4. TDD 接入 fast CLI/Application、工作树、批准、RED/GREEN、产出物和 implementation。
5. 实现 fast Skill profile、guidance 和 Vitest 模板并验证标准 profile 不变。
6. 运行已批准的聚焦 pytest 和最小 Python compileall，登记产出物与实施状态。

## 五、阶段依赖

状态模型和诊断组件先稳定，CLI 编排才消费；Skill profile 必须在 confirm 自动推进节点前可用；
只有真实 RED 后才写生产实现；聚焦 GREEN 后才执行最小编译和交付登记。

## 六、风险与回退方案

所有代码只写入 `praxis/REQ-20260724-001__轻量缺陷快车道v1` 工作树。任一编排或验证失败时
保留当前需求、binding、日志和改动并停止；不删除工作树、不重置分支、不提交或推送。新 CLI
和 profile 可整体回退，既有标准 operation 不改变。
