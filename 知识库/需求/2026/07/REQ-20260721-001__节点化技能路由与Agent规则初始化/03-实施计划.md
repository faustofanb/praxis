# 实施计划

## 一、总体目标

实现可审计的节点化 Skill 路由，并在 Praxis 工作空间初始化中生成 Codex `AGENTS.md` 与
Claude Code `CLAUDE.md` 的同源管理区块。

## 二、范围说明

1. 扩展 Skill 元数据和路由上下文，支持节点、意图、仓库类型、业务域、Agent 角色、风险、
   产出物、预算、批准状态和 Provider 可用性。
2. 为方法 Skill 建立丰富的节点 Provider 规则，记录可信上游来源、版本和许可证。
3. 输出必需、条件触发、需批准、不可用四类路由决策及选择原因。
4. 增加 Skill 调用开始/完成凭证和必需 Skill 节点门禁，不再用 `skill.routed` 代表调用。
5. 增加统一 Agent 指引渲染器，以 Praxis 管理区块更新 `AGENTS.md`、`CLAUDE.md`，保留用户
   自定义内容。
6. `workspace bootstrap` 集成指引生成，同时提供无 CodeGraph/DBX 副作用的独立刷新入口，
   供 MOM 与 AOTU 现有工作空间初始化。

## 三、不在本次范围内的内容

- 不在 bootstrap 中自动下载或执行第三方 Skill。
- 不自动启动 reviewer/tester Agent。
- 不自动运行 lint、format、typecheck、测试或覆盖率。
- 不自动提交 MOM/AOTU 业务仓库。

## 四、阶段划分

### 阶段一：节点路由模型

- 新增节点策略、Provider 元数据、路由决策与调用凭证服务。
- 扩展 CLI、Application 和 MCP 只读/审计接口。

### 阶段二：Agent 指引初始化

- 新增同源管理区块渲染器。
- 集成 `workspace bootstrap` 和独立 `workspace guidance` 操作。

### 阶段三：Skill 规则丰富

- 调查：`brainstorming`、`ponytail`、`file-search`。
- 计划：`writing-plans`、`ponytail`。
- 实现：业务 Skill、语言规范、`karpathy-guidelines`，缺陷条件触发
  `systematic-debugging`。
- 验证/评审：只在人工批准后路由测试、验证和代码评审 Skill。
- 交付：条件路由分支收尾 Skill；提交、推送、合并仍服从用户授权。

### 阶段四：业务工作空间生成

- 使用独立安全入口为 MOM 与 AOTU 生成/刷新 `AGENTS.md`、`CLAUDE.md`。
- 只检查文件内容与 Git diff，不运行项目测试或质量复核。

## 五、阶段依赖

节点路由模型先于指引渲染；指引渲染完成后才能安全刷新 MOM/AOTU。代码修改必须位于
`REQ-20260721-001` 绑定的隔离工作树。

## 六、风险与回退方案

- 管理区块解析异常时停止写入，保留原文件。
- 必需 Provider 缺失时输出明确缺失项，不自动安装。
- 路由策略变更可通过删除新增状态记录和恢复原 Skill 元数据回退。
- MOM/AOTU 文件只新增或更新 Praxis 管理区块，可由 Git 恢复该区块。
