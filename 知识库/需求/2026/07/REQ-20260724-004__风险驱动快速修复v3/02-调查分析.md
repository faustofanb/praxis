# 调查分析

## 1、需求目标

将小修复从“完成命令和门禁”改为“消除会影响实现或交付判断的不确定性”，提供单文件 `fast_fix` 终结通道。

## 2、业务背景

现有 `fix start|finish` 已能处理 1–3 个业务文件，但仍会创建测试、编译、Skill 与多项产出物流程。对单注解、空值判断、条件或参数调整，这些治理动作可能超过修复本身，并诱导低价值测试。

## 3、当前实现

- `SmallFixService` 负责 `fix.start` 与 `fix.finish`，会创建工作树、收据、测试与类型检查验证。
- CLI 与 `Application.execute` 分别维护参数映射和 operation 分派。
- 工作区 bootstrap 通过 managed block 生成 `AGENTS.md` / `CLAUDE.md` 指引。
- 运行时状态、验证拒绝、产出物和 implementation 均已有服务可复用。

## 4、涉及业务域

Praxis CLI、快速通道、Agent 执行指引、需求交付登记。

## 5、涉及系统和仓库

单仓库 `praxis-next`。

## 6、涉及模块

`cli`、`application`、`fastlane`、`agents.guidance`、`verification`、`artifacts`、`requirements`。

## 7、业务规则

- `fast_fix` 只接受一个业务文件和 annotation/null_guard/condition/parameter 四类微小变更。
- 不得涉及数据库结构、API 契约、公共接口、迁移、事务或并发。
- 用户的快速修复与拒绝验证表达在执行扩展前形成约束。
- `fix record` 不运行测试、编译、全量类型检查或 reviewer。
- 验证被拒绝时如实登记，不创建反射、源码匹配或调用形状测试。
- 命令必须对应具体风险与会变化的决策；有等价证据时复用。

## 8、数据口径

证据身份由工作树绑定、HEAD 与目标文件内容指纹组成；相同身份的重复登记必须幂等复用。

## 9、接口与数据流

`praxis fix record <requirement-id> --file ... --verification ... --reason ...` → CLI → `Application.execute("fix.record")` → `FastFixService.record` → 风险/范围校验 → 运行时证据 → 验证省略记录 → 单一代码产出物 → implementation。

## 10、现有能力复用

复用 `StateStore`、工作树 binding、Git argv runner、`VerificationService`、`ArtifactService`、`RequirementService` 和 agent managed block；不新增依赖或数据库表。

## 11、代码图谱调查

根项目当前没有 `.codegraph`，CodeGraph 明确返回不可查询且要求不要自行初始化。隔离工作树创建后由 Praxis 后台任务初始化索引，状态为 `CODEGRAPH_FRESH`，索引 HEAD 为 `17fb33b6d45ec3fa41bbd0026490d53d3c0510e0`。

编辑前 `codegraph_explore` 证据：

- CLI `main` 仅由 `src/praxis/__main__.py` 调用，缺少直接覆盖；因此增加公共参数映射行为测试。
- `SmallFixService` 有 6 个调用/测试依赖，保持 `fix start|finish` 不变，新增独立 `FastFixService`。
- `RequirementService` 有 45 个调用方、`ArtifactService` 有 21 个调用方；新服务只复用公开登记能力，不修改其现有行为。
- `AgentGuidanceService.render` 有 4 个调用方，并由 `tests/test_agent_guidance.py` 与 e2e 测试覆盖；仅扩展 managed block。

## 12、数据库调查

不涉及业务数据库或 Praxis schema 变更。

## 13、影响范围

新增一个 CLI 子命令与内部服务，更新 agent 指引和聚焦行为测试；既有 `fix start|finish` 与标准 profile 保持兼容。

## 14、风险分析

- 公共 CLI 分派变更可能影响既有参数解析。
- 一次性治理登记必须避免部分写入和重复产出物。
- 过度自动识别变更类型会产生误判，因此结构边界自动检查、语义类型由显式参数或可审计原因推断。
- `fix record` 不得暗中执行验证命令。

## 15、待确认事项

无。用户已明确要求完整实施，并持续推进到提交、安装；推送仍只在精确目标与提交范围获准后执行。

## 16、调查证据

- 用户提供的完整风险驱动规则和期望命令。
- 现有 README、`SmallFixService`、CLI、应用分派及 agent guidance 搜索结果。
- CodeGraph 根项目无索引诊断，以及需求工作树 fresh 调用链与 Blast Radius。

## 17、分析结论

采用兼容增量设计：保留 v2 小修复通道，新增只负责“收尾登记”的 `fast_fix` 服务；执行价值判断放入 agent 核心约束，避免为价值判断再增加关键路径命令。
