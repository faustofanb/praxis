# 调查分析

## 1、需求目标

把 Skill 选择从单纯关键词匹配升级为工作流节点策略。路由必须同时考虑节点、任务意图、
系统与业务域、仓库类型、Agent 角色、风险、产出物、上下文预算和人工批准状态，并为
Codex 与 Claude Code 生成一致的根级工作规则。

## 2、业务背景

现有会话已经出现“执行了命令但没有真实调用 Skill”“调查阶段没有方法技能”“测试和
质量复核未经批准自动执行”等问题。仅把 Skill 文本加入上下文不足以证明 Skill 被调用，
也无法作为节点流转门禁。

## 3、当前实现

- `SkillRegistry.route()` 只按 `triggers` 对意图字符串做包含匹配。
- `route_context()` 虽支持系统、业务域、仓库角色、阶段、产出物和风险评分，但上下文编译
  当前没有使用它。
- `praxis-system-development` 声明了 `delegates`，但 `Skill` 数据模型和注册器没有解析该字段。
- `skill.routed` 只记录 Skill 被选择进入上下文，不代表开始或完成调用。
- Agent 会话中的 `skills` 只是字符串列表，未校验可用性，也没有节点完成门禁。
- `workspace.bootstrap` 初始化 CodeGraph、技能候选和数据库发现，但不生成 `AGENTS.md` 或
  `CLAUDE.md`。

## 4、涉及业务域

- Praxis 插件开发
- Agent 工作流治理
- Skill 发现、路由和审计

## 5、涉及系统和仓库

- 系统：`praxis-next`
- 仓库：`praxis-next` Python 插件
- 下游工作空间：MOM、AOTU

## 6、涉及模块

- `src/praxis/skills/registry.py`
- `src/praxis/context/service.py`
- `src/praxis/agents/service.py`
- `src/praxis/application.py`
- `src/praxis/workspace/`
- `skills/`
- Codex 与 Claude Code 初始化适配器

## 7、业务规则

1. 节点基线 Skill、条件 Skill、需批准 Skill 必须分开表达。
2. 调查节点至少需要 `brainstorming` 与 `ponytail`，并根据任务加载文件检索、系统化调试、
   DBX 或业务 Skill。
3. 测试、质量复核、reviewer/tester Agent 永远属于需批准策略；被路由不等于已获批准。
4. 路由结果必须给出原因、来源、版本、许可证、内容哈希、风险和预算。
5. 必需 Skill 缺失时阻断节点完成，不得静默回退为普通提示词。
6. 第三方 Skill 不得在初始化时自动下载或执行；安装必须单独获得用户批准。
7. `AGENTS.md` 与 `CLAUDE.md` 由同一渲染器生成 Praxis 管理区块，保留区块外用户内容。

## 8、数据口径

建议将 Skill 生命周期区分为：

- `planned`：节点策略已选中。
- `available`：当前 Agent 可解析该 Skill。
- `invoked`：Agent 已声明开始使用，并记录版本与内容哈希。
- `completed`：Skill 流程结束并记录结果。
- `blocked_pending_approval`：匹配但尚未获得人工批准。
- `unavailable`：必需 Skill 未安装或来源不可信。

## 9、接口与数据流

`工作流节点 + 任务上下文` → `节点策略候选` → `条件/风险/批准过滤` → `预算与去重` →
`路由计划` → `Agent 调用声明` → `调用完成凭证` → `节点流转门禁`。

## 10、现有能力复用

- 复用 `SkillRoutingContext`，增加节点、仓库类型、批准状态和可用 Skill 清单。
- 复用技能元数据中的来源、版本、风险、预算和内容哈希。
- 复用 SQLite 哈希审计链记录路由和调用凭证。
- 复用 `workspace.bootstrap` 生成 Agent 根级规则。
- 复用 Praxis 现有 requirement/worktree/CodeGraph 门禁。

## 11、代码图谱调查

本轮只读调查通过源码入口和 `rg` 完成。未执行 CodeGraph 构建或同步，因为用户没有授权
额外初始化/质量操作；实现前应在隔离工作树中使用已有 CodeGraph 生命周期。

## 12、数据库调查

本需求不涉及数据库结构或业务数据读写，不调用 DBX。

## 13、影响范围

- Skill 元数据解析和路由输出结构。
- 上下文编译与审计事件。
- requirement 节点流转门禁。
- Agent 会话启动与调用凭证。
- 工作空间 bootstrap 产物。
- Codex/Claude Code 插件缓存与后续新会话加载。

## 14、风险分析

- 直接复制全部第三方 Skill 会造成重复、版本漂移和上下文膨胀。
- 自动安装第三方包会引入供应链风险；本轮 Skills CLI 搜索已因需要执行第三方 npm 包而被
  安全策略阻止，后续不得绕过。
- 把 `routed` 当成 `invoked` 会形成虚假审计。
- 节点必需 Skill 过多会超出上下文预算，需要按能力去重和优先级裁剪。
- 自动覆盖现有 `AGENTS.md`/`CLAUDE.md` 会破坏项目自定义规则，必须使用管理区块。

## 15、待确认事项

采用“可信外部 Skill 作为可选 Provider + Praxis 自有稳定节点策略”的方式，不在 bootstrap
中自动安装第三方代码。该设计待用户确认后进入实施计划和工作树创建。

## 17、分析结论

该缺陷需要新增节点策略层和调用凭证层，而不是继续增加触发关键词。推荐以 Praxis 节点
能力为稳定接口，把已安装的可信方法 Skill 和业务 Skill 作为 Provider；初始化只生成路由
规则与缺失报告，不执行第三方安装。Codex 与 Claude Code 共用同一策略和审计协议。
