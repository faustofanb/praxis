# 调查分析

## 目标与根因

现有 `fast-defect-v1` 只能新建需求，并仍依赖标准工作树同步；既有小修复因此路由为
`profile: standard`，脏模板工作区会阻断创建。目标是提供关联既有需求的薄层快速通道。

## 现有能力

- `FastLaneService` 已提供 argv 解析、风险扫描、诊断基线和增量比较。
- `ArtifactService.add(..., "code-change")` 可登记单一 Git 变更产出物。
- `WorktreeService` 已集中处理命名、binding、本地文件、setup preflight 和 CodeGraph。
- `RequirementService.reopen()` 支持 verifying → in_progress。

## CodeGraph 调查

首次编辑前在 binding `WT-REQ-20260724-003--praxis-next` 上取得新鲜索引：

- 索引提交：`c686eebcdf1beac71ba82078cb42df3ef1cbb024`
- 调用链：CLI `_operation` → `PraxisApplication._execute` →

- Blast Radius：`create_for_requirement` 有 3 个生产调用方；RequirementService 有 42 个调用方；
  ArtifactService 有 19 个调用方；CLI/application 由接口与 dispatch 测试覆盖。

编辑后 affected 遍历 37 个依赖，变更集中在 CLI、application、fastlane、routing、
worktree、artifact 与对应测试。

## 规则结论

1. start 只关联已有需求；ready 进入开发，verifying 自动 reopen。
2. 模板分支 fetch 后解析为 commit，工作树直接从该 SHA 创建，不检查或清理模板工作区。
3. finish 以真实 Git 状态和 numstat 判定 1–3 个已跟踪业务文件、最多 80 行。
4. `{files}` 作为独立 argv token 才启用范围类型检查；否则缓存模板基线并比较诊断多重集合。
5. 测试文件不计业务文件数，但显式纳入完整代码变更产出物。
6. 越界保留需求和工作树并降级，不自动回滚。

## 风险

固定 revision 必须验证为 commit；已有 binding 的 base revision 不一致时失败关闭。风险内容只检查
本次新增 diff 行，避免因文件中既存锁/事务词汇误降级。所有测试、diff-check 和类型检查均使用
argv 经 RTK 执行。
