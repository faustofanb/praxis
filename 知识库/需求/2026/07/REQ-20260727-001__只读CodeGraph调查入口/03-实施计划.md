# 实施计划

## 一、总体目标

提供可验证、无持久化副作用的 Plan Mode CodeGraph 调查入口，并消除 investigating 路由和
Agent 指引之间的语义不一致。

## 二、范围说明

- 新增 `CodeGraphService.investigate(target, purpose)`。
- 新增 `praxis codegraph investigate <target> --project <project> --purpose <purpose>`。
- 增加 Service、CLI、应用分发和 guidance 的聚焦回归测试。
- 更新 `codegraph-impact-analysis`、`praxis-requirement-workflow`、
  `praxis-system-development` 及 README 的双通道说明。

## 三、不在本次范围内的内容

- 不改变现有 `query/explore/node/affected` 的同步和持久化行为。
- 不允许 Plan Mode 初始化或同步索引。
- 不允许 Plan Mode 使用 `--binding` 或 `--worktree`。
- 不新增数据库、需求或产出物持久化模型。
- 不降低正式高风险编辑前的 binding、freshness、调用路径和 Blast Radius 门禁。

## 四、阶段划分

### 阶段 1：Service TDD

1. 在 `tests/test_codegraph.py` 增加成功路径测试，证明只调用原生 `status` 和 `explore`、
   返回 `persisted:false`、HEAD/dirty fingerprint，且不写 CodeGraph 元数据或审计。
2. 增加 stale/mismatch 状态拒绝测试，证明不会调用 `explore`。
3. 执行：
   `rtk test .venv/bin/pytest -q --no-cov tests/test_codegraph.py -k plan_mode_investigation`
   并观察 RED。
4. 在 `src/praxis/codegraph/service.py` 写最小实现，再执行同一命令观察 GREEN。

### 阶段 2：CLI 与分发 TDD

1. 在 `tests/test_interfaces.py` 和 `tests/test_application_dispatch.py` 增加失败测试。
2. 执行：
   `rtk test .venv/bin/pytest -q --no-cov tests/test_interfaces.py tests/test_application_dispatch.py -k codegraph_investigate`
   并观察 RED。
3. 在 `src/praxis/cli/__init__.py` 和 `src/praxis/application.py` 增加最小映射。
4. 执行同一命令观察 GREEN。

### 阶段 3：工作流说明 TDD

1. 在 `tests/test_agent_guidance.py` 增加断言，要求 guidance 同时包含 investigating
   跨模块触发、`codegraph investigate`、`persisted:false` 和正式 binding 审计边界。
2. 执行：
   `rtk test .venv/bin/pytest -q --no-cov tests/test_agent_guidance.py`
   并观察 RED。
3. 更新 guidance、三个 Skills 与 README，再执行同一命令观察 GREEN。

### 阶段 4：最小编译与交付

TDD GREEN 后执行 Python 最小编译：
`rtk proxy -- .venv/bin/python -m compileall -q src/praxis`。
完整回归、Ruff、类型检查、覆盖率和代码质量复核不包含在开发授权内，另行申请。

## 五、阶段依赖

Service 只读契约先稳定，CLI 与分发依赖该契约；工作流说明依赖最终命令形状。首次代码编辑前
必须创建需求工作树，并在绑定工作树中完成正式 CodeGraph 影响分析。

## 六、风险与回退方案

改动均为向后兼容新增。若原生 CodeGraph `status` 契约不满足校验要求，返回明确失败码，不回退
到会同步或持久化的常规 `explore`。回退实现时删除新子命令和方法，现有行为不受影响。
