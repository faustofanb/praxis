# 调查分析

## 1、需求目标

为 Plan Mode 增加无需需求编号和 worktree binding 的只读 CodeGraph 调查入口，并让
`AGENTS.md` 对 investigating 节点的说明与真实 Skill 路由一致。

## 2、业务背景

跨 PAD、BFF、Service 和数据库的根因调查已经满足 `cross-module` 条件。现有
`node-routing.toml` 会在 investigating 节点条件路由 `codegraph-impact-analysis`，但生成的
Agent 指引只强调“高风险改动编辑前”，容易把 CodeGraph 错解为纯开发门禁。

## 3、当前实现

- `references/node-routing.toml` 已将 `codegraph-impact-analysis` 配置到
  `investigating`，并包含跨模块、公共接口和影响范围等触发条件。
- `src/praxis/agents/guidance.py` 只描述绑定工作树内的编辑前 CodeGraph 审计，没有 Plan
  Mode 调查入口。
- `CodeGraphService.query/explore/node` 统一经过 `_query()`；`_query()` 会调用
  `ensure_fresh()`。当只有仓库原生 `.codegraph` 索引而 Praxis 尚无元数据时，
  `_recover_existing_index()` 会写入 CodeGraph 元数据和审计事件。
- `codegraph-impact-analysis` Skill 强制从需求 binding 解析实际工作树，无法用于无需求的
  Plan Mode。
- 数据库已有独立的 `database investigate` 模式，返回 `persisted:false`，可作为接口模式
  参考，但 CodeGraph 不应复用数据库安全规则。

## 4、涉及业务域

Praxis 插件开发工作流、Plan Mode 调查、CodeGraph 影响分析。

## 5、涉及系统和仓库

系统与仓库均为 `praxis-next`。

## 6、涉及模块

- `praxis.codegraph.service`
- `praxis.application`
- `praxis.cli`
- Agent guidance 生成器
- `praxis-requirement-workflow`、`praxis-system-development` 和
  `codegraph-impact-analysis` Skills

## 7、业务规则

- Plan Mode 调查只允许项目画像中已登记仓库的现有索引。
- 不要求需求编号或 worktree binding。
- 不得初始化、同步、恢复并持久化索引元数据，亦不得写需求、产出物或审计状态。
- 索引必须初始化完成、无 pending refs、无 pending changes、无 worktree mismatch，且
  `projectPath` 必须等于项目画像解析出的仓库路径。
- 返回值必须包含调查目的、目标 symbol、项目路径、当前 HEAD、dirty fingerprint 以及
  `persisted:false`。
- 临时结果只能作为诊断证据；进入实施后仍必须在绑定工作树中执行正式
  `codegraph-impact-analysis`。

## 8、数据口径

CodeGraph 原生 `status --json` 是索引有效性的只读来源；Git HEAD 与 staged、unstaged、
untracked 内容共同形成当前 dirty fingerprint。二者共同写入临时 scope，不写 Praxis
StateStore。

## 9、接口与数据流

`praxis codegraph investigate <target> --project <project> --purpose <purpose>`
→ `PraxisApplication._codegraph`
→ `CodeGraphService.investigate`
→ 原生 `codegraph status`
→ 校验现有索引
→ 原生 `codegraph explore`
→ 返回 exploration 与临时 scope。

## 10、现有能力复用

复用 `WorkspaceService` 的项目路径解析、`GitSnapshot.capture()` 的 HEAD/dirty fingerprint
以及现有 `Runner` 注入方式；不引入新依赖、新存储模型或第二套项目定位逻辑。

## 12、数据库调查

不涉及数据库。

## 13、影响范围

新增一个 CLI 子命令和一个 Service 方法；现有 `status/build/sync/ensure-fresh/query/explore`
行为保持不变。文档影响覆盖自动生成的 Agent 指引和三个 Praxis Skills。

## 14、风险分析

- 若只包装现有 `explore`，会通过 `ensure_fresh()` 产生持久化副作用，违反
  `persisted:false`。
- 若允许自动同步，就会把 Plan Mode 调查扩展为仓库写操作。
- 若只检查 `.codegraph` 目录存在，会接受未完成、路径错配或落后的索引。
- 若放宽正式 Skill 的 binding 规则，会削弱编辑前审计。

## 15、待确认事项

无。用户已明确要求保留正式审计约束，并在确认上述双通道设计后要求“修复”。

## 16、调查证据

- `skills/praxis-system-development/references/node-routing.toml`：investigating 已包含
  CodeGraph 条件路由。
- `src/praxis/codegraph/service.py`：常规查询通过 `ensure_fresh()`，恢复路径写 StateStore。
- `src/praxis/agents/guidance.py`：仅有编辑前绑定工作树说明。
- `docs/superpowers/plans/2026-07-23-plan-mode-database-investigation.md`：已有
  `persisted:false` 调查模式参考。

## 17、分析结论

采用独立 `codegraph investigate` 只读入口，不修改常规查询与正式审计语义。Agent guidance
明确 investigating 的跨模块触发条件，并说明 Plan Mode 与正式 change audit 的证据边界。
