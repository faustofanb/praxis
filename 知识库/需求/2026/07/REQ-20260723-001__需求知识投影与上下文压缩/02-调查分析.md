# 调查分析

## 1、需求目标

在不增加泛化 Skill 的前提下，降低 Praxis 工作流的命令与上下文开销，并修复需求知识投影的可审阅性和可信度：需求目录按编号前置排序，文档按固定序号排序；历史布局可幂等迁移；产出物保存独立归档；业务域和系统画像提供结构化、可验证的上下文；CLI 支持紧凑输出。

## 2、业务背景

当前流程可以交付，但人工审阅和 Agent 上下文成本偏高。中文简称前置导致目录无法按时间排序，文件名没有阅读顺序；产出物主要保存易失的源路径；业务域文档只有标题；系统画像虽已扫描部分证据，但投影过于简略；CLI 默认完整输出也会消耗大量 token。

## 3、当前实现

- `RequirementPathPolicy.directory_name` 生成 `<中文简称>__<需求编号>`，多个服务直接引用未编号文件名。
- `repair_projections` 只重放待处理 outbox，不主动迁移全部历史投影。
- `ArtifactService.add` 保存哈希和源路径但不归档源文件；数据库 SQL 由调用方预写入需求目录，是少数例外。
- `DomainService` 只存编号、名称和系统列表，文档只有 frontmatter 与一级标题。
- `PortraitService` 已扫描技术栈、命令、分支、数据库、CI、CodeGraph 和运行态，但文档只展示少量信息。
- CLI 默认打印完整 `Result.data`。

## 4、涉及业务域

- `plugin-development`：Praxis 插件的生命周期、治理、知识投影和发布。

## 5、涉及系统和仓库

- 系统与仓库：`praxis-next`

## 6、涉及模块

- `praxis.naming`、`praxis.documents`、`praxis.knowledge`
- `praxis.artifacts`、`praxis.database`
- `praxis.domains`、`praxis.workspace`
- `praxis.portraits`、`praxis.cli`、`praxis.application`

## 7、业务规则

- 新目录为 `<需求编号>__<中文简称>`；工作树命名不变。
- 文档序号是稳定协议，迁移目标冲突且内容不同时阻断，不覆盖。
- 归档文件有独立 SHA-256；源文件漂移或删除不破坏已归档证据。
- 业务域和画像只投影可验证事实，未知内容不猜测。
- 紧凑输出只影响终端展示，不裁剪状态、审计和 `--json` 完整结果。

## 8、数据口径

- 需求文档布局版本：`2`
- 源哈希与归档哈希均使用 SHA-256。
- 画像按仓库结构、入口、接口、数据、运行和验证证据分组。

## 9、接口与数据流

`StateStore requirement` → `RequirementPathPolicy` → `RequirementProjector` → 版本化知识目录。

`artifact add` → 校验源文件 → 复制/生成归档快照 → 计算双哈希 → 写状态与产出物清单。

## 10、现有能力复用

- 复用原子写入与现有状态事务，不增加存储依赖。
- 复用产出物类型映射和画像扫描证据。
- `--json` 保留完整机器结果，默认人类输出使用摘要。

## 11、代码图谱调查

仓库没有 `.codegraph/` 索引，按工具指引回退到 `rg` 和定向源码读取。路径策略被投影器、需求服务、上下文、任务、MCP、数据库和产出物共同使用，因此迁移必须集中在路径策略并提供兼容定位。

## 12、数据库调查

不变更业务数据库结构。Praxis SQLite schema 保持兼容，只扩展 JSON 记录字段。

## 13、影响范围

- 高：历史知识目录迁移、产出物验证语义。
- 中：领域与画像文档格式、CLI 人类可读输出。
- 低：状态存储 schema 和既有 `--json` 自动化调用。

## 14、风险分析

- 历史目标冲突：检测后阻断。
- 用户手工修改旧文档：仅在目标不存在或内容相同时迁移。
- 源位于归档目录：识别同一路径，避免自复制。
- 脚本依赖输出：`--json` 继续返回完整结构。
- 画像过度推断：只展示扫描事实和来源。

## 15、待确认事项

无。用户已授权分阶段持续推进到提交、推送和安装；采用向后兼容、冲突即阻断策略。

## 17、分析结论

对比了三种方案：只修改新建规则无法修复历史；保留旧目录并创建别名会产生双写和漂移；版本化布局配合幂等迁移能保持单一事实源。选择第三种。

产出物采用“归档快照 + 源引用”，不只留引用，也不复制整个仓库。业务域和画像采用确定性结构化代码能力，不创建泛化工作流 Skill。
