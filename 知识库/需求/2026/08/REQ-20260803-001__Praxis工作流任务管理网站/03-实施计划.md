# 实施计划

## 一、总体目标

交付一个可在本机启动的 `praxis web` 工作流驾驶舱：默认只读查看真实需求，所有写操作通过明确的固定 API 和单角色 Broker 会话进入现有 Praxis 生命周期。

## 二、范围说明

1. 新增 Workflow Dashboard 聚合服务和固定生命周期进度模型。
2. 扩展 RequirementService、StateStore、Application、Broker、AgentSessionService 与 CLI。
3. 新增 Python 标准库 HTTP server、Cookie/Origin 防护、固定 REST API、静态 HTML/CSS/ES Modules 看板。
4. 支持工作树 preview → ensure、上下文、Skill、门禁、证据和 Agent prepare/launch/stop/finish/receipt。
5. 新增聚焦 TDD 测试、README 使用说明和静态资源打包配置。

## 三、不在本次范围内的内容

远程访问、账号系统、数据库写入/任意 SQL、部署、任意命令或 PID 管理、WebSocket、React/Vite、新运行时依赖、独立子任务表、截止日期、优先级、完整回归/lint/typecheck 和浏览器自动化验收。

## 四、阶段划分

1. `captured/investigating`：完成需求登记、调查、Skill 路由和 CodeGraph 影响证据。
2. `analyzed/planned`：冻结模块边界、固定 API、权限矩阵、生命周期与进度口径。
3. `in_progress`：先写失败测试，再实现 Dashboard、Broker/Application、Agent 和 Web server。
4. `implemented/verifying`：实现静态页面、CLI、文档和打包，运行聚焦测试与最小编译。
5. `completed`：补齐产出物、验收结论并保留审计/Agent receipt。

## 五、阶段依赖

需求分析和计划文档完成后才创建隔离工作树；CodeGraph fresh evidence 完成后才编辑高风险代码；RED 测试完成后才进入实现；聚焦测试和最小编译通过后才记录实施结果。

## 六、风险与回退方案

权限新增保持角色白名单默认拒绝；Agent launch 默认关闭，stop 失败闭锁；preview 指纹变化拒绝 ensure；若静态资源打包失败，回退为源码树运行路径并修正 Hatch include，不引入依赖；若现有测试契约冲突，优先保持既有 API envelope 和能力语义。

|---|---|---|---|---|---|
| 聚焦测试 | 可自动化 | 填写已批准的最小测试命令 | 本地依赖/配置 | 待确认 | 待执行 |
| 最小编译 | 可自动化 | 填写 `minimum-module-compile` 精确命令 | 模块工具链 | 待确认 | 待执行 |
