# 实施计划

## 一、总体目标

将 AGENTS.md / CLAUDE.md 每会话静态注入的约 200 行 managed 块瘦身为「指针 + 不变式 + 表格」（约 45 行），操作细则去重收敛到内置 `praxis-requirement-workflow` SKILL.md 作为唯一权威源按需加载。行为保证不变：强制门禁仍在代码侧 fail-closed。收益：每会话静态 token 约减 3/4，消除两客户端与 SKILL.md 的三重复。

## 二、范围说明

1. 重写 `AgentGuidanceService._managed_content` 为紧凑版：保留工作空间身份、入口单行、需求/工作树不变式、禁止未绑定目录改代码、fail-closed 声明、Skill 调用协议（含 `--used-skill` 单行示例）、节点 Skill 策略表、仓库模板分支表、项目规则与业务 Skill 来源。
2. 操作细则（fast_fix、RTK、TDD、命令预算、证据指纹缓存、subagent、investigate 细则）迁出到 `skills/praxis-requirement-workflow/SKILL.md` 作为唯一权威源；AGENTS/CLAUDE 只保留指向该 Skill 的一行指针 + 一行 fast_fix 触发识别。
3. 逐条比对 AGENTS 既有细则与 SKILL.md，补齐 SKILL.md 缺失条目（以 AGENTS 正文为基准），保证无细则丢失。
4. 拆分测试断言：保留的指针/不变式/表格断言更新措辞；迁出的细则断言改为断言 SKILL.md 含该内容（双验证：AGENTS 含指针 + SKILL.md 含细则）。
5. `workspace guidance` 重新生成 AGENTS.md / CLAUDE.md，核对漂移项（如节点表当前显示 writing-plans，策略实为 wayfinder）。

## 三、不在本次范围内的内容

- 不修改状态机、fail-closed 门禁、审计链、worktree binding、pre-commit 等代码侧强制。
- 不修改 `_merged_content` 的 marker 保护逻辑。
- 不重写 SKILL.md 结构，只补齐缺失细则条目。
- 不改动节点路由策略（node-routing.toml）、MCP broker、DBX、CodeGraph、Worktrunk 引擎。
- 不执行完整回归、lint、typecheck、覆盖率或 reviewer/tester Agent（需独立授权）。

## 四、阶段划分

1. **TDD RED**：先改 `tests/test_agent_guidance.py` 与 `tests/test_workflow_optimization.py` 断言（保留项更新措辞、迁出项改断言 SKILL.md），运行聚焦测试观察预期失败。
2. **GREEN**：实现 `guidance.py` 紧凑版 `_managed_content` + 补齐 SKILL.md 缺失细则，运行聚焦测试通过。
3. **最小模块编译**：GREEN 后只编译最小受影响模块并记录命令与 exit code。
4. **重新生成受管文件**：`workspace guidance` 重新生成 AGENTS.md/CLAUDE.md，核对漂移项。
5. **登记与交付**：登记产出物与 implementation，推进 verifying，如实登记未执行验证，提交并合并回模板分支。

## 五、阶段依赖

- 工作树必须在第一次业务代码编辑前 active；需求状态需达到 ready。
- TDD RED 必须在实现前完成；GREEN 后独立执行最小模块编译。
- AGENTS/CLAUDE 重新生成依赖 GREEN 后的生成器。

## 六、风险与回退方案

- 细则迁出后、skill 加载前存在规则暴露窗口：缓解 = 强制在代码侧、不变式保留在 AGENTS、workflow skill 全节点 required。
- 测试断言大改可能掩盖回归：以「断言 SKILL.md 含细则 + AGENTS 含指针/不变式」双验证替代单点字符串。
- 生成结果变更导致 AGENTS.md/CLAUDE.md 工作树 diff：预期行为，随需求提交一并登记。
- 若 SKILL.md 补全不彻底：以 AGENTS 既有正文为基准逐条比对，实施阶段列出缺口清单核对。
