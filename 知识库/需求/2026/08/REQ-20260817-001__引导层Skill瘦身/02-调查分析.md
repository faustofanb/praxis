# 调查分析

## 1、需求目标

将 AGENTS.md / CLAUDE.md 每会话静态注入的约 200 行 managed 块瘦身为「指针 + 不变式 + 表格」（约 45 行），操作细则（fast_fix、RTK、TDD、命令预算、证据指纹缓存、subagent 等）去重收敛到内置 `praxis-requirement-workflow` SKILL.md 作为唯一权威源、按需加载。行为保证不变：强制门禁仍在代码侧 fail-closed。

## 2、业务背景

AGENTS.md（与 CLAUDE.md 由同一 `AgentGuidanceService.render` 生成）的 managed 块与内置 `praxis-requirement-workflow/SKILL.md` 存在大量逐条重复：Praxis 入口解析、fast_fix 例外、禁止机械执行命令与预算、证据指纹缓存、TDD + approval receipt、RTK 代理、Skill 调用协议、subagent/fork_turns、worktree 命名与 pre-commit guard。同一规则以「静态注入 + 重复 skill 文件」两份形式存在：静态注入每次会话固定占用上下文，不因任务类型裁剪。

## 3、当前实现

- `src/praxis/agents/guidance.py:_managed_content`（第 37–205 行）用约 170 行列表拼接生成受管块，同时写入 AGENTS.md 与 CLAUDE.md（二者内容几乎相同）。
- `skills/praxis-requirement-workflow/SKILL.md`（188 行）已包含大部分操作细则（fast_fix、TDD、RTK、skill 调用协议、subagent、investigate 细则），与 managed 块大量重叠。
- 受管块尾部「节点 Skill 策略表」「仓库模板分支表」「项目规则与业务 Skill 来源」由数据生成，路由与工作树操作需要，保留。
- 测试 `tests/test_agent_guidance.py` 对 AGENTS.md 内容有约 60 条字符串断言，其中既有指针/不变式/表格类，也有将迁出的细则类；`tests/test_workflow_optimization.py` 有 3 条 guidance 断言。

## 4、涉及业务域

- plugin-development
- workflow governance

## 5、涉及系统和仓库

- 系统：`praxis-next`
- 仓库：`praxis-next`（python-plugin）

## 6、涉及模块

- `praxis.agents.guidance`（唯一业务代码改动）
- `skills/praxis-requirement-workflow/SKILL.md`（细则权威源补齐）
- `tests/test_agent_guidance.py`、`tests/test_workflow_optimization.py`（断言拆分）
- AGENTS.md / CLAUDE.md（受管内容重新生成）

## 7、业务规则

1. 强制门禁（状态机、fail-closed、审计链、worktree binding、pre-commit）保持在代码侧，不因引导层瘦身弱化。
2. 每会话必须保底暴露的「不变式」：需求先登记、确认改代码才建工作树、禁止未绑定目录改代码、状态流转 fail-closed、Skill 调用协议。
3. 操作细则以 `praxis-requirement-workflow` SKILL.md 为唯一权威源；AGENTS/CLAUDE 不再重复细则正文，只保留指向该 Skill 的指针。
4. 动态数据（节点策略表、模板分支表、业务 Skill 来源）继续由 guidance 生成注入，不静态化。
5. fast_fix 触发识别保留一行：用户说“快速修复”等表达时按 Skill 的 fast_fix 例外记录 mode=fast_fix。

## 8、数据口径

- managed 块行数从约 170 行降至约 45 行（含表头与表格）。
- SKILL.md 在现有 188 行基础上补齐从 AGENTS 迁出的缺失细则（逐条比对后仅缺失少量条目）。
- 重复内容不允许同时存在于 AGENTS/CLAUDE 与 SKILL.md；同一规则只保留一份正文。

## 9、接口与数据流

`AgentGuidanceService.render` → 生成紧凑 managed 块 → 写入 AGENTS.md/CLAUDE.md；SKILL.md 由节点路由在进入节点时加载，细则随用随取。

## 10、现有能力复用

- SKILL.md 已含绝大部分细则，只需补齐缺失条目，不需要重写。
- `_merged_content` 的 marker 保护逻辑（AGENT_GUIDANCE_MARKERS_INVALID）保持不变。
- `tests/test_agent_guidance.py` 的骨架与 marker 校验测试保持，仅拆分批量字符串断言。

## 11、代码图谱调查

本需求只改 `guidance.py` 一个业务文件 + SKILL.md + 测试断言，不涉及事务、锁、原生 SQL、并发、公共接口、结构迁移或高扇出路径；`AgentGuidanceService` 的调用方仅 CLI/MCP 的 `workspace.guidance` 操作与 `workspace.bootstrap`，影响面收敛。不初始化代码索引。

## 12、数据库调查

不涉及数据库结构、数据或 DBX 查询。

## 13、影响范围

- `AgentGuidanceService._managed_content` 输出变化 → 影响每次 `workspace guidance` 生成结果。
- `tests/test_agent_guidance.py` 约 60 条断言拆分（保留项更新措辞、迁出项改断言 SKILL.md）。
- `tests/test_workflow_optimization.py` 3 条 guidance 断言同步。
- AGENTS.md/CLAUDE.md 重新生成后，当前工作树会出现受管块 diff——这是本需求预期的行为。

## 14、风险分析

- 细则迁出后、skill 加载前存在规则暴露窗口：缓解 = 强制在代码侧、不变式保留在 AGENTS、workflow skill 全节点 required。
- 测试断言大改可能掩盖回归：以「断言 SKILL.md 含细则 + AGENTS 含指针/不变式」双验证替代单点字符串。
- 生成结果变更导致 AGENTS.md/CLAUDE.md 工作树 diff：预期行为，需在需求提交中一并登记。
- 若 SKILL.md 补全不彻底，细则缺失：以 AGENTS 既有正文为基准逐条比对，缺口在实施阶段列出清单核对。

## 15、待确认事项

- 无（方案已在计划阶段确认：指针 + 不变式 + 表格形态；细则唯一权威源为 SKILL.md）。

## 17、分析结论

推荐「引导层瘦身 + Skill 唯一权威源」形态：AGENTS/CLAUDE 保留指针、不变式与动态表格，细则收敛到 SKILL.md 并按需加载；先拆分测试断言（TDD RED），再实现紧凑版生成器（GREEN），最后重新生成受管文件并核对漂移。
