# 实施计划

## 一、总体目标

打通 fast-lane「完工后现实回退」与「错误自助恢复」，落实四项优化：
1. **P0**：`fix start` 接受 completed 需求，自动 completed → in_progress（带原因审计）；
2. **P1**：`fix start`/`fast start` 支持 `--worktree <需求ID>` 复用既有绑定工作树（校验 repository 一致）；
3. **P1**：`FAST_LANE_TYPECHECK_NOT_CONFIGURED` 的 data 给恢复动作；`praxis doctor` 对强类型仓库缺 typecheck_commands 输出警告；
4. **P2**：errors 目录补齐 46 个 fast-lane/fix 错误码（`FAST_LANE_*`、`SMALL_FIX_*`），错误 JSON 可查恢复动作。

## 二、范围说明

- **P0 方案一**：`fix start`（small_fix.start）接受 completed 状态，先 `reopen(from_status="completed")` 回 in_progress 再继续；
  `requirement reopen` 与 `requirement.fix start` 共用同一回退路径，reopen 白名单扩展为 verifying/implemented/completed。
- **P1 --worktree 复用**：CLI `fix start`/`fast start` 增加 `--worktree <需求ID>`；
  命中时校验 binding.repository_id == 目标 repository_id，复用该工作树（跳过 create_for_requirement）；未命中时保持新建默认行为。
- **P1 恢复动作**：`_typecheck_argv` 对 `FAST_LANE_TYPECHECK_NOT_CONFIGURED` 返回
  `data={"hint": "在 praxis.toml 的 [[systems.repositories]] 段添加 typecheck_commands，例如 typecheck_commands = [\"mvn ...\"]"}`；
  `praxis doctor` 检查 `kind` 为强类型（java-maven 等）仓库缺 `typecheck_commands` 时输出 warning 条目。
- **P2 errors 补齐**：`src/praxis/guides/errors.py` 批量补 46 个 fast-lane 错误码条目，
  hint/next_step 覆盖分类：状态机回退、worktree、typecheck、diff、RED/GREEN、test 命令、finish 收尾等。

## 三、不在本次范围内的内容

- P2 的 `praxis guide <scenario>` 场景名可执行化（独立增强，后续评估）；
- P3 各项：portrait 测试命令语义过滤、TDD vs 仓库禁测约定、CWD/路径自动向上定位、constraint 通道语义；
- 状态机分级（小需求合并 investigating/analyzed/planned 节点）；
- `verification fail` 子命令（验收失败登记 + 自动回退，涉及验证维度数据结构，单独评估）。

## 四、阶段划分

1. **调查**：对照代码核实四项优化点现状（已完成，见 02-调查分析）。
2. **计划**：本文件 + worktree preview/ensure。
3. **TDD 实施**：先写聚焦测试观察 RED → 实现 → GREEN → minimum-module-compile。
4. **验收**：聚焦测试 + CLI 复演（completed fix start、--worktree 复用、errors 查询、doctor 警告）。
5. **收尾**：产出物登记、门禁推进、合并回模板、重装全局 praxis、重新生成 mom/aotu guidance。

## 五、阶段依赖

- fix 接受 completed 依赖 reopen 白名单扩展（P0 与 reopen 共享回退路径）；
- --worktree 复用依赖 binding 解析（已有 resolve_worktree_binding）；
- errors 补齐独立，可在实施末尾统一补。

## 六、风险与回退方案

- P0 扩展 reopen 白名单会放宽“只有 verifying/implemented 可 reopen”的既有门禁：
  缓解 = 仅 completed 因“完工后缺陷”回退，reason 必填、审计留痕，不改变其它状态路径。
- --worktree 复用若 binding 状态非 active 或 repository 不一致：返回明确错误，不回退到新建。
- errors 补齐量大：机械批量补，逐码核对 hint/next_step 语义。
