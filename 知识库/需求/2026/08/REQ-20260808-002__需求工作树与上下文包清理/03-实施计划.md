# 实施计划

## 一、总体目标

为需求派生资源（工作树、分支、上下文包、binding）提供两层清理机制：
1. **终态自动清理**：需求到达 `archived`/`cancelled` 时，自动清理其工作树、分支、上下文包
  与 runtime_state 记录，清理结果审计留痕。
2. **显式清理命令**：新增 `praxis worktree cleanup <requirement_id>`（默认 dry-run 预览，
  `--confirm` 执行），兜底清理孤儿 binding（旧式 `req/REQ-*`）与终态遗留。

## 二、范围说明

- `src/praxis/worktree/service.py`：新增 `cleanup_for_requirement(requirement_id, *, dry_run)`
  方法——按 `requirement_id` 枚举 binding（含旧式 branch-keyed 孤儿）、安全判定
  （binding status、分支合并状态、worktree 工作区状态）、逐条复用 `remove()` 语义执行。
- `src/praxis/context/service.py`：新增 `cleanup_for_requirement(requirement_id, *, dry_run)`
  方法——删除 `生成内容/上下文包/CTX-*` 中 requirement_id 匹配的文件，清理
  `context`/`context_current`/`context_previous` scope 记录。
- `src/praxis/knowledge/requirements.py`：`transition()` 到 ARCHIVED/CANCELLED 后触发
  两个 cleanup（fail-open：失败只审计不阻断状态推进）。
- `src/praxis/application.py`：`worktree.cleanup` operation 路由。
- `src/praxis/cli/__init__.py`：`worktree cleanup` 子命令（`--requirement` 必填 +
  `--dry-run`/`--confirm` 互斥，默认 dry-run）。
- `tests/test_worktree_cleanup.py`：聚焦单元测试（tmp_path 隔离）。

## 三、不在本次范围内的内容

- 不做 `agent session`/委派子会话的清理（属 REQ-20260808-001 Gap 2 范畴，另立需求）。
- 不做 `repair` 批量孤儿清扫（`worktree cleanup --all`）；孤儿通过显式命令按需求清理，
  无需求归属的孤儿由 `repair orphan-cleanup` 单独立项。
- 不改动 mom/aotu 任何代码。

## 四、阶段划分

1. **TDD RED**：先写聚焦测试（安全判定阻断、dry-run 不执行、终态清理执行、孤儿清理、
  上下文包清理），观察预期失败。
2. **TDD GREEN**：实现 `cleanup_for_requirement`（worktree + context），测试转绿。
3. **最小模块编译**：`uv run python -m py_compile` 对应模块。
4. **接线**：CLI 子命令 + application 路由 + transition 自动触发，编译验证。
5. **自举验证**：对已终态/孤儿需求跑 dry-run 预览，确认输出符合预期。
6. **提交**：工作树内提交，需求推进 implemented。

## 五、阶段依赖

阶段 2 依赖阶段 1 的 RED 基线；阶段 3-6 依赖阶段 2 GREEN。

## 六、风险与回退方案

- **误删未合并分支**：安全判定强制检查 `git branch --merged <default_branch>`，
  未合并则阻断该条目并报告，不删除。dry-run 默认开启，`--confirm` 才执行。
- **worktree 删除失败**：逐条目独立处理，失败记 `worktree.cleanup_failed` 审计，
  不中断其他条目，返回汇总。
- **上下文包误删**：只删 `requirement_id` 字段匹配的 CTX 记录与文件；
  `context_current`/`context_previous` 按 identity 中的 requirement_id 过滤删除。
