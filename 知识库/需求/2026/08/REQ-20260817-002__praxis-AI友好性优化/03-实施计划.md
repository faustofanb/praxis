# 实施计划

## 一、总体目标

降低 AI（Codex/Claude Code）使用 praxis 的认知负担：首次接触能以任务导向方式快速上手，遇错能自助恢复，高频输出减少噪音。本次落地高优先级方案 A（任务导向引导）+ B（错误自助），方案 C/D/E 视授权分批。

## 二、范围说明

- **方案 A：`praxis guide` 任务导向引导**
  - 新增 `praxis guide [--scenario <new-requirement|create-worktree|tdd|verify|fast-fix>]`，按当前工作区状态输出「我现在该做什么」的命令序列。
  - 受管块补一行指针：「不确定下一步时运行 `praxis guide`」。
- **方案 B：错误自助**
  - 集中登记约 100 个错误码（中文含义 + 恢复动作 + 可复制恢复命令），存为数据文件。
  - 错误输出默认追加 `hint`/`next_step`；新增 `praxis errors [code]` 查询目录。
  - 错误码集合本身不变，`ok/code/data` 契约不变。
- **方案 C（输出裁剪）/D（上下文裁剪）/E（节点恢复指引）**：本次不实施，作为后续批次；若用户追加批准则纳入。

## 三、不在本次范围内的内容

- 不改状态机、门禁判定、worktree 绑定逻辑。
- 不改 MCP operations 与 `--json` 完整包络契约（方案 C 未实施）。
- 不改错误码集合（只新增 hint/next_step 与查询入口）。
- 不触碰 mom/aotu 等下游业务仓库代码。

## 四、阶段划分

1. 方案 A：`praxis guide` 命令 + 场景模板 + 受管块指针。
2. 方案 B：错误码 catalog 数据 + 输出渲染 + `praxis errors` 查询。
3. 验证：聚焦测试（CLI 映射/guide 输出/错误 hint）+ 最小模块编译 + 用户批准的完整回归/lint/typecheck。
4. 登记产出物与实施，推进验证与收尾。

## 五、阶段依赖

- A 依赖：`src/praxis/cli/__init__.py` 命令注册、`_compact_payload` 输出模式。
- B 依赖：错误码静态抽取（`rg 'Result\(False, "[A-Z_]+"'`）、新增数据文件、渲染层扩展。
- 两者独立可并行；共用 CLI 命令注册与 `--summary/--json` 机制。

## 六、风险与回退方案

- 默认输出增强若破坏机器消费：缓解 = 契约只由 `--json` 保证，默认渲染只增 hint/next_step 字段；回退 = 移除渲染扩展。
- `praxis guide` 输出若信息过载：缓解 = 按场景分页、只列当前状态相关步骤；回退 = 收敛模板。
- 错误码 catalog 文案工作量：缓解 = 分批登记，先覆盖高频（REQUIREMENT_*/WORKTREE_*/SKILL_*/APPROVAL_* 约 40 个），其余后续补齐。
