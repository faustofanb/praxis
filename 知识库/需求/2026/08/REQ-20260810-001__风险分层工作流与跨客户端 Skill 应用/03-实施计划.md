# 实施计划

## 一、总体目标

实现统一风险 taxonomy、轻量 lane 的高风险 fail-closed 与 standard handoff、Fast/Small 的 Skill gate 证据闭环，并增加 Codex/Claude workspace application 入口。保持 Praxis 的需求、工作树、安全、审计和状态职责，不自动安装第三方 Skill。

## 二、范围说明

1. 新增共享风险策略与 canonical aliases；Fast/Small 和 NodeSkillRouter 使用同一 eligibility 结果。
2. 轻量 profile 命中 CodeGraph/高风险时停止并返回 standard handoff。
3. Fast/Small finish 复用 `SkillInvocationService` 记录结构化 outcomes/gate；small-fix 使用 focused verification 语义。
4. 抽取 workspace client projection，新增 `workspace install-agent --agent codex|claude-code|all`，保留 `workspace install-claude` 兼容入口。
5. 两端刷新 guidance/MCP；Claude 保留 skills symlink 与 binding guard；Codex 只应用实际可验证的 plugin/workspace 投影，不伪造 hook。
6. 更新测试和 README，记录 source/path/hash、missing/conflict、lane handoff 与幂等行为。

## 三、不在本次范围内的内容

- 不联网下载或安装 Matt Pocock、obra 或其他第三方 Skill。
- 不重写 MCP broker、DBX、Worktrunk、CodeGraph 引擎。
- 不扩展 Oh My Pi/Kimi 安装流程。
- 不猜测 Claude marketplace/private manifest schema。
- 不顺手修复 `agent launch` 未把 session-rendered Claude settings 真正传入客户端的问题，除非统一 apply 证明该修复是必要且已有明确客户端契约。
- 不覆盖现有 `.codex-plugin/plugin.json` 用户修改。

## 四、阶段划分

1. **治理模型**：新增 taxonomy；先写风险 profile 和 route gate 聚焦测试并观察 RED。
2. **Lane 实现**：最小修改 Fast/Small/Router，补 handoff、structured outcomes 和 gate；保持现有验证命令语义。
3. **客户端投影**：抽取 Claude integration 的共享部分，新增统一 CLI/application dispatch 与 Codex/Claude 结果模型。
4. **文档与集成测试**：补 lane 决策表、Fast Lane 说明、安装/apply 边界和幂等/冲突测试。
5. **最小模块编译与独立验证**：TDD GREEN 后只运行受影响 Python 模块的最小编译/静态检查；其他回归、lint、typecheck、quality review 另行授权。

## 五、阶段依赖

- taxonomy 在 Fast/Small/Router 之前完成。
- route eligibility 测试 RED 后才能编辑实现。
- workspace apply 复用现有 Claude integration 测试，再扩展 Codex；客户端字段只采用已验证契约。
- 文档更新随实现稳定后完成。
- 工作树必须在第一次业务代码编辑前 active；需求状态需达到 ready。

## 六、风险与回退方案

- 若风险别名无法安全归一化，按 high-risk 处理并 handoff standard，不允许放行。
- 若 Codex 的 workspace Skill 投影字段无法验证，只输出已存在 plugin manifest 的 apply/diagnostics，不写猜测配置。
- 若 structured Skill gate 与历史 lane 状态不兼容，保留已有 route/audit，返回缺失 gate，不将实现标记为 passed。
- 若客户端配置存在冲突，跳过并报告，不覆盖用户文件。
