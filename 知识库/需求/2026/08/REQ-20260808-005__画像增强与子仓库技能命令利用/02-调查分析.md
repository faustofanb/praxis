# 调查分析

## 1、需求目标

扫描 mom/aotu 后发现三类问题：(1) 项目画像描述不够——技术栈只做文件标记检测、命令是通用模板，
缺模块结构/关键目录/业务说明；(2) 各子仓库自带技能和规则没利用上——skill 目录与
CLAUDE.md/AGENTS.md 未被 praxis 发现登记；(3) 编译测试命令不准确——web 实际是 pnpm，
backend 是多模块 maven，画像却写 npm/mvn package 通用命令。

## 2、业务背景

mom/aotu 是子仓库聚合工作空间（8 个子仓库）。praxis 的 PortraitService 按仓库路径扫描，
但只做通用检测，不读取子仓库自身沉淀的规则（CLAUDE.md/AGENTS.md）和技能（docs/skills、
.cursor/skills、skills/ 目录），导致画像单薄、子仓库经验资产不可复用。

## 3、当前实现

- `PortraitService._technology`（portraits/service.py:220）：按文件标记检测技术栈
  （pom.xml→Java/Maven、package.json→Node.js/Vue），不读仓库内容。
- `PortraitService._commands`（service.py:252）：通用命令模板（mvn package / npm run build /
  npm test），不读 package.json scripts、pom.xml 模块、CLAUDE.md 常用命令段。
- `SkillRegistry.workspace`（skills/registry.py:64）：只扫描工作空间根 knowledge/skills，
  不扫描子仓库内部技能目录。
- `praxis.toml` 支持 lint-command/typecheck-command/test-command 配置（Project dataclass 已有
  字段），但 mom/aotu 未配置，画像输出为空。

## 4、现状证据（扫描实测）

- mom/ifc-mes-pda/skills/validate-die-location（库位校验技能，SKILL.md 完整）
- mom/ifc-mom-column-max/.cursor/skills/fullstack-development
- mom/ifc-web-mom-max/docs/skills/：bill-lowcode-sourcecode-form、bill-pageid-modal-form、gen-api
- aotu/ifc-web-mom-max/docs/skills/：9 个（ifc-api-crud、ifc-module-extraction、ifc-vxe-crud、
  ifc-business-selector、ifc-lowcode-crud、ifc-configure-pattern 等）
- aotu/ifc-mom-column-max/CLAUDE.md（319 行，含 mvn clean install -pl lamp-mes -am -DskipTests）
- aotu/ifc-web-mom-max/CLAUDE.md（1337 行）+ AGENTS.md（75 行）
- mom web 实际 packageManager 是 pnpm@10.22.0，scripts 含 check:type/check/build:antd；
  画像却写 `npm run build`/`npm test`
- mom/aotu 的 praxis.toml 均未配置 lint/test/typecheck 命令

## 5、涉及模块

`src/praxis/portraits/service.py`（画像扫描与渲染）、`src/praxis/skills/registry.py`
（子仓库技能发现）、`src/praxis/workspace/service.py`（Project 字段已支持命令配置）、
`src/praxis/skills/importer.py`（技能登记到 knowledge/skills）。

## 6、修复方向

1. **画像增强**：`_technology`/`_commands` 扩展——读取 package.json scripts（找 build/test/
   lint/typecheck 语义脚本，优先 pnpm）、pom.xml 模块列表、CLAUDE.md/AGENTS.md 常用命令段
   （```bash 块）与项目概述段（前 50 行摘要）；输出模块结构（pom modules）、关键目录
   （业务语义目录）、规则文件摘要。
2. **子仓库技能利用**：`SkillRegistry.workspace` 或新入口扫描子仓库技能目录
   （docs/skills、.cursor/skills、skills/），登记到 knowledge/skills 供路由使用。
3. **命令配置优先**：praxis.toml 显式配置 > 仓库实际命令检测 > 通用模板。

## 7、风险分析

- CLAUDE.md 1337 行过大：只提取关键段（概述 + 常用命令块），不全文纳入画像。
- 子仓库技能与现有业务技能重名：登记时按仓库前缀命名空间（如 business.mom.web.gen-api），
  冲突时保留现有。
- 命令检测误判：scripts 语义匹配要保守（build/test/lint/typecheck 精确匹配），
  显式配置始终优先。

## 8、分析结论

三个修复点集中在 portraits/service.py + skills/registry.py，无数据库变更、无公共接口变更，
不触发 codegraph-impact-analysis 强制条件。命令检测要有显式配置兜底。
