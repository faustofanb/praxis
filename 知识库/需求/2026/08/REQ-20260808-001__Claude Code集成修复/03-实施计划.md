# 实施计划

## 一、总体目标

新增一个 `praxis workspace install-claude` CLI 操作：给定当前工作空间根目录，
(1) 合并写入 `.mcp.json` 注册 `praxis` MCP server，
(2) 在 `.claude/skills/` 下为已解析的技能目录（工作空间自身技能目录 + 全局 bundled 技能）建立
符号链接，
(3) 生成/合并 `.claude/settings.local.json` 的 `PreToolUse` hook，指向按 `praxis.toml`
仓库列表动态生成的守卫脚本 `.claude/hooks/praxis-binding-guard.sh`，
(4) 追加 `.gitignore` 忽略这些派生路径。
在 praxis-next、mom、aotu 三个工作空间上运行该命令。

## 二、范围说明

- `src/praxis/skills/routing.py` 或新文件 `src/praxis/skills/deployment.py`：新增
  `resolve_workspace_skills(root)`（复用 `_installed_skills` 的 rglob 模式，扫描范围改为工作空间
  根目录，排除 `.git/.worktrees/node_modules/dist/.claude`）。
- 新文件 `src/praxis/workspace/claude_integration.py`（或并入
  `src/praxis/agents/guidance.py` 同级）：`ClaudeIntegrationService.install(root)`，产出
  `.mcp.json`、`.claude/skills/*`、`.claude/settings.local.json`、
  `.claude/hooks/praxis-binding-guard.sh`、`.gitignore` 追加项，均为合并写入。
- `src/praxis/cli/__init__.py`：新增 `workspace install-claude` 子命令与 operation 路由。
- `tests/`：聚焦单元测试覆盖合并写入的幂等性和不覆盖已有内容的行为。

## 三、不在本次范围内的内容

- 不修复 `AgentSessionService._json_config` 的委派子会话 hook schema（Gap 2）——范围更大，
  且需要先确认本次项目级方案的实际效果，作为后续独立需求处理。
- 不新增 Claude Code 插件市场注册（`.claude-plugin` 的正式 install 流程）。
- 不改动 mom/aotu 任何业务子仓库代码。
- 不建立 mom/aotu 自己的 Praxis 需求记录——这是工具/配置操作，不是业务代码变更。

## 四、阶段划分

1. praxis-next：TDD 实现 `resolve_workspace_skills` + `ClaudeIntegrationService.install`
   + CLI 接线。
2. `minimum-module-compile`：`uv run python -m py_compile` 对应模块 + 聚焦 pytest。
3. 在 praxis-next 自身运行 `workspace install-claude` 校验（自举）。
4. `uv tool install --reinstall --from . praxis-workflow` 把修复发布到全局 `praxis`。
5. 在 mom、aotu 分别运行 `workspace install-claude`；mom 额外验证新 hook 与既有
   `check-praxis-binding.sh` 逻辑等价后可删除旧脚本，aotu 是全新生成。

## 五、阶段依赖

阶段 2-5 依赖阶段 1 的 GREEN；阶段 4-5 依赖阶段 3 自举验证通过，避免把未经验证的实现发布到
两个生产工作空间。

## 六、风险与回退方案

- 若 `.mcp.json`/`settings.local.json` 已存在冲突键，命令必须报告冲突并停止，不做静默覆盖
  （回退：保留原文件，人工合并）。
- 若 mom 新 hook 与旧 `check-praxis-binding.sh` 行为不一致，保留旧脚本文件、只切换
  `settings.local.json` 指向哪一个，不删除旧脚本直到确认一致。
- 项目级 `.claude/skills/` 若被证实 Claude Code 不读取（见验证矩阵"需环境"项），符号链接机制
  本身无害（不影响现有功能），只是价值待确认；不回退，等用户新会话验证结果决定是否改用其他
  部署路径。
