# 全栈交付检查清单

## 后端检查

- 需求已拆解，生成边界与手工补齐边界明确。
- 若涉及数据库设计，已参考现有 PostgreSQL 表结构。
- Flyway SQL 已在指定迁移目录或对应月份目录下维护。
- 模块归属正确。
- 包结构、类名、继承关系符合 lamp 现有实现。
- Controller 只做请求转发与校验。
- Service 承担事务与业务编排。
- Manager 没有承接完整业务流程。
- 没有明显的 N+1、循环查库、无分页大查询。
- 若未明确跨模块抽象需求，则保持单体实现，没有提前做微服务拆分。

## 前端检查

- 目录归属在 apps/web-antd 同域下。
- 若当前需求属于 MES job 分组，文件已落在既有 job 或 jobTime 目录。
- 导入路径使用 `#/`。
- API、页面、schema、hook、store 分责清晰。
- 同域 API 已优先复用，没有无必要重复接口。
- `int64` 字段已建模为 `string`。
- 表单场景已处理默认值、回填、校验、提交闭环。
- 页面已接入基本权限、消息提示与国际化。

## 契约检查

- 前后端接口路径一致。
- 请求参数与后端 VO 对齐。
- ResultVO、分页结构、状态语义一致。
- 删除、状态修改、树操作等扩展动作语义一致。

## 验证检查

- 代码生成结果已作为基础骨架复用，并说明了人工补齐范围。
- 至少执行了一类校验。
- 若无法执行，已说明阻塞原因。
- 已给出联调结果或手动验证建议。
- 已说明本次变更涉及的前后端文件范围。
