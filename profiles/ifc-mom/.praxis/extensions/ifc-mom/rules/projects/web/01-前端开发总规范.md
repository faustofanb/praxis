# 前端开发总规范

## 适用范围

适用于 `ifc-web-mom-max` 的通用前端开发。

## 核心约束

- 使用 Vue 3 Composition API 与 `script setup`
- 所有导入路径统一使用 `#/`
- 页面、API、schema、hook、store 分责清晰
- 超过三个调用点的逻辑要抽离
- 优先复用 `Page`、`useVbenVxeGrid`、`useDynamicTableBuilder`、`useVbenModal`、`useVbenForm` 等现有能力
- 简单样式优先 Tailwind，复杂样式用 BEM 或等价命名

## 交互要求

- 权限控制、消息通知、国际化不能缺位
- 列表、查询、详情、保存、删除、状态变更要形成闭环

## 性能要求

- 优先路由级或组件级懒加载
- 避免无必要的大对象响应式和重复请求
- 优先复用现有 hook 或 store 的缓存和封装

## 提交与测试

- Web 仓库提交前先读取并遵循 commitlint scope；后台提交使用 `fix(@vben/web-antd): <中文主题>`，正文空一行后按编号写改动点和测试或保障。
- 不使用 `fix(web)` 这类未授权 scope。
- Vitest 不可靠接受目录 glob filter 时，改用显式 spec 文件路径；不要因为目录 glob 返回 “No test files found” 判定无测试或测试失败。
- 用户要求带 spec 时，feature cherry-pick 必须保留对应 spec；若 spec 不进入 feature，必须说明用户未要求或存在明确交付豁免。
