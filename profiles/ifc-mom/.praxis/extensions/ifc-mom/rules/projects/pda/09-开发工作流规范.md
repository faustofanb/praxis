# 开发工作流规范

## 常用命令

### 开发

```bash
pnpm dev
pnpm dev:h5
pnpm dev:mp-weixin
```

### 检查

```bash
pnpm lint
pnpm lint:fix
MOM_PDA_FULL_TYPECHECK=1 pnpm type-check
```

- 普通源码变更默认只执行变更文件范围内的定向 lint 或等价轻量检查，不默认执行全项目 `pnpm type-check`。
- 项目级 `pnpm type-check` 需要用户明确要求、收尾策略要求或显式设置 `MOM_PDA_FULL_TYPECHECK=1`。
- 涉及接口生成、接口定义或上游发布/场景分支已有变更时，运行 `pnpm alova-gen` 前必须确认需求 worktree 已基于 `praxis.projects.toml` 的 `defaultBranch` 创建，且创建前已同步 `upstreamBranch -> defaultBranch`；若绕过统一 worktree 命令，必须手工 `/usr/bin/git fetch origin <upstreamBranch>` 或 `rtk git fetch origin <upstreamBranch>` 并对齐对应场景分支后再生成。

### 提交

```bash
pnpm commit
```

## 提交规范

- 使用 conventional commits
- 提交前通过 husky 与 lint-staged 自动检查

## 构建

- H5、各小程序和 App 平台分别使用对应构建命令
- 构建产物位于 `dist/build/` 下各平台目录

## 最佳实践

- 页面放 `src/pages/`
- 复用组件放 `src/components/`
- 业务逻辑封装为 composables
- 关注图片、缓存和响应式数据带来的性能影响
