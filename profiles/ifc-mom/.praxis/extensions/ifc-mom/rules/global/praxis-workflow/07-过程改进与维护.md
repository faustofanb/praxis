# 过程改进与维护

## 记录边界

- `todo.md` 只记录任务中实际暴露、尚未解决的工作流缺口或用户明确要求后续固化的事项。
- 普通任务计划、代码清单、临时待办、例行复盘和没有行动项的总结不写入 `todo.md`。
- 已解决的问题直接更新对应规则、skill、脚本或配置，不同时保留重复待办。
- 规则维护、工具配置和过程改进属于非业务需求，不写入 `docs/02-req/`；确需跟踪时使用 `.praxis/requirements/`。
- 只有产生可复用结论时才新增过程记录，不为每个业务需求强制生成复盘文档。

## 维护原则

- 入口文档只保留导航和少量硬门禁，细则只保留一个权威来源。
- 项目事实来自 `praxis.projects.toml`；共享 profile 不覆盖路径、分支、验证命令或需求记录。
- 新增子项目先更新项目索引，再补充确实需要的项目规则。
- 新规则只提升到适用的最小范围，不为假设场景预建全局约束。
- 删除或改名命令时同步更新命令表、引用它的规则和聚焦测试。

## 最小检查

- 修改通用初始化或同步脚本：运行插件测试和全新工作区初始化冒烟检查。
- 修改 profile 脚本：运行对应的聚焦测试。
- 修改规则或 skill：运行命令引用/路径检查；没有模板系统时不要求模板生成。
- 提交、交付、清理、远程操作和生产数据仍需用户明确确认。
