# 轻量 ETL 调查与口径治理

## 定位

本文件约束报表/ETL 需求的数据调查、字段口径、指标版本和对账治理。涉及真实数据、字段来源、表关系、报表口径、SQL 或迁移时，本文件必须和 `03-调查门禁.md`、`mom-database-investigation` 一起使用。

## dbx 只读调查

- 默认使用 dbx MCP，只查 `LOCAL` / `DEV`；`PRO` 或疑似生产库必须先获得用户明确许可。
- 先执行 `dbx_list_connections` 确认连接名、数据库和环境。
- 使用 `dbx_list_tables` 定位表/视图；使用 `dbx_execute_query` 查询 `information_schema`、`pg_catalog`、字段注释、索引、约束、样例和分布。
- 样例查询必须带业务条件、时间范围、主键/业务单号或合理 `limit`；禁止无条件扫大表。
- 无法连接数据库时，结论必须标注“未连接数据库，待人工确认”，不能把猜测写成事实。

## 口径卡

每个指标至少回答：

- 按什么粒度统计。
- 按什么时间字段和业务日归属统计。
- 哪些状态、类型、工序、组织、设备或物料计入。
- 指标公式、单位、空值和异常值处理方式。
- 口径版本、适用范围、下游引用和已知限制。

## 对账与追溯

- 至少提供正例、反例、边界样例和总数对账路径。
- 复杂口径应提供 `rpt_debug_*` 明细追溯视图或函数。
- 口径争议不能只靠页面观察关闭，必须回到真实库样例、源码契约或业务确认记录。
- 口径变更必须记录影响范围：MagicAPI、积木报表、大屏、导出、权限和历史需求。

## 落盘要求

- 调查过程写入需求目录 `01-需求分析拆解/` 或 `04-产出物/关联信息调查/`。
- 可复用口径写入中心 ETL 资产目录的 `指标口径卡.md`、`对账说明.md` 和 `验证SQL.sql`。
- 文档必须包含查询环境、dbx 连接名、schema、关键 SQL/对象、样例特征和未决项。
