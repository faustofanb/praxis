# 轻量 ETL 报表工作流

## 定位

适用于报表、统计、驾驶舱、MagicAPI、积木报表及口径治理。默认采用 PostgreSQL 函数/视图沉淀规则与口径，MagicAPI 暴露稳定接口，积木报表负责展示；不默认引入调度平台、物理数仓或独立报表库。

## 最小流程

1. 明确需求边界、指标粒度、时间/状态/单位口径和菜单归属。
2. 用只读数据库调查确认真实表、字段、关联、样例、数据量和索引；无法连接时明确标注未验证。
3. 选择最小可复用分层：`rpt_base_*` 标准化、`rpt_rule_*` 公共规则、`rpt_biz_*` 业务事实、`rpt_metric_*` 指标、`rpt_api_*` 接口、`rpt_debug_*` 对账。
4. 将中心资产写入 `docs/03-etl/<应用>/<系统>/<菜单路径>/<中文主题>/`，需求目录保存证据、决策、反链和迁移前产物。
5. 用正例、反例、边界样例、总数对账、权限、分页排序和性能证据验证；交付时列出未验证项。

初始化入口：

```bash
task etl -- init
task etl -- subject <应用> <系统> <一级菜单> <中文主题> --menu-path <菜单路径> --requirement <需求名> --menu-code <编码> --menu-name <名称>
task etl -- tree
```

## 按需路由

不要一次加载全部细则，只读取当前任务涉及的文件：

- 建目录、资产台账或 PostgreSQL 分层：`08a-轻量ETL资产与分层.md`。
- 查库、字段口径、指标版本或对账：`08b-轻量ETL调查与口径治理.md`。
- MagicAPI、积木报表、大屏或接口兼容：`08c-轻量ETLMagicAPI与积木报表.md`。
- SQL 产出物、正式迁移、验收或交付说明：`08d-轻量ETL产出物与验收.md`。

同时遵循 `.praxis/extensions/ifc-mom/skills/global/mom-lightweight-etl-report/SKILL.md` 的触发与执行约束；需要模板时再读取其 `references/templates.md`，不要预加载全部参考资料。

## 不可省略的边界

- 真实数据、字段来源和 SQL 结论必须有数据库或源码证据，猜测不能写成事实。
- `docs/03-etl/资产索引.md` 是唯一全局 ETL 资产台账。
- 新资产使用正式版表述；是否已落库由路径、迁移状态和交付说明区分。
- 正式 Flyway 目录只能在用户确认收口后写入，且可追溯到需求目录中的中间产物。
- 大表、高频刷新和跨月聚合必须在实时函数、普通视图、物化视图、汇总表之间记录性能选择及刷新/补算策略。
