# 轻量 ETL 资产与分层

## 定位

本文件是 `08-轻量ETL报表工作流.md` 的分拆索引，专门约束中心 ETL 资产目录、资产台账和 PostgreSQL 逻辑分层。报表、统计、驾驶舱、MagicAPI 和积木报表任务先读主规则，再按任务需要读取本文件。

## 资产目录

- 可复用报表口径、函数、视图、对账说明、MagicAPI 契约和积木报表契约必须沉淀到中心 ETL 目录，不只留在单次需求目录。
- 新主题目录使用真实菜单层级：`docs/03-etl/<应用>/<系统>/<一级菜单>/<二级菜单>/.../<中文主题>/`。
- `<应用>` 只使用顶部应用分类：`运营平台`、`基础平台`、`仓库管理`、`供应协同`、`生产制造`、`质量管理`、`设备管理`、`计划排程`。
- 需求目录 `04-产出物/ETL资产链接.md` 保存中心资产反链；中心资产 README 和口径卡互链，并兼容 Tolaria frontmatter、H1 和 wikilink 关系。
- `docs/03-etl/资产索引.md` 是全局资产台账，单个需求或资产目录不得维护同名局部资产索引。

## 分层职责

- `rpt_base_*`：只做源对象只读封装、字段标准化、时间/状态/单位归一和溯源字段保留，不做复杂指标。
- `rpt_rule_*`：沉淀跨报表复用的日期、状态、单位、比例、权限、指标版本等公共规则函数。
- `rpt_biz_*`：固化业务事实和业务口径，保留对账所需源对象引用。
- `rpt_metric_*`：固化指标粒度、指标公式、过滤条件和指标版本。
- `rpt_api_*`：提供稳定 API 契约，输出前端友好字段，不暴露源系统复杂结构。
- `rpt_debug_*` / `rpt_doc_*`：分别用于明细追溯、差异排查和口径说明入口。

## 建模约束

- 本项目默认不新增 schema，全部使用 `public` schema，并通过对象名前缀表达层级。
- 禁止一个视图同时承担清洗、口径、聚合和展示四类职责。
- 公共函数优先兼容增强既有函数，避免为少量字段组合新增 wrapper。
- 函数签名或返回类型变化必须提供旧函数 drop 策略、兼容说明和依赖排查清单；默认不使用 `cascade` 掩盖依赖问题。
- 多个函数复用同一字段集合时，优先沉淀组合类型、视图或稳定公共函数作为字段契约。

## 脚本入口

```bash
task etl -- init
task etl -- subject <应用> <系统> <一级菜单> <中文主题> --menu-path <一级菜单/二级菜单/...> --requirement <需求名> --menu-code <菜单编码> --menu-name <菜单名称>
task etl -- tree
```
