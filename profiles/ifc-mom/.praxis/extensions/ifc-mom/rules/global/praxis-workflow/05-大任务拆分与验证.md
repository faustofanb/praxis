# 大任务拆分与验证

## P0（必须）

### 任务拆分

- 跨项目或跨模块大任务先创建主任务 worktree/分支作为集成分支。
- 子任务按可独立理解、独立开发和独立验证的边界切分（后端、Web、PDA、大屏、报表、文档或明确子域）。
- 子任务必须有清晰修改边界和最小验证命令。
- 子任务完成后先回并主任务，在主任务分支执行 L1 或 L2 验证后再交付。
- 不得为无独立验证价值的微改动强制拆分。
- 口径与契约是并发前提：先固化口径，再做并行实现。
- 主对话反复补上下文时，说明输入包或边界不完整，应立即补齐并重分。

### 验证等级与最小门禁

默认 L1。业务需求验证不以全局校验为默认门禁。

- L0：只做脚本语法、项目映射、变更范围识别，不强制编译。
- L1：按 Git 变更推断最小范围做 lint、局部编译、局部单测。
- L2：公共包、构建配置、跨多个业务域/子项目或发布前才提升。
- 全局校验被脚本默认包含时，优先拆出变更范围命令；无法执行的原因需写入交付说明。
- 前端/PDA eslint 禁止默认全仓扫描，只能扫描需求变更范围内仍存在的源码文件。
- 前端/PDA type-check 禁止默认全仓扫描；没有变更范围内专用 type-check 时，默认只执行定向 lint 或等价轻量检查，项目级 type-check 需要用户明确要求或显式环境开关。
- 完成态必须先有验证证据：命令、退出码、关键输出或无法验证原因；不得先宣布完成再补验证。
- 缺陷修复至少满足“失败证据 -> 修复点 -> 复测证据”三段式；没有可运行复测时，交付说明必须列出人工复核路径。
- 影响共享逻辑、接口契约、SQL/迁移、异步流程或权限口径时，优先补一个最小回归用例或门禁断言；确实不写测试时说明原因。

### 微小参数变更快速通道

适用于常量、参数 key、默认值、SQL 模板和已有页面参数切换；模板、样式、路由、Store、API 契约或公共逻辑同时变化时退出快速通道。

1. 恢复同名需求已有 worktree；没有同名 worktree 时按正常入口创建。
2. 修改代码或 SQL，执行 `git diff --check`。
3. Java 只做变更模块 compile，Web/PDA 只 lint 变更文件；可执行查询 SQL 补 `EXPLAIN`。
4. 只在参数传递或消费契约需要保护时补测试，最多 1–2 条契约测试。
5. 生产代码最后一次修改后只执行一次项目 `verify`；之后若只新增测试，仅重跑对应测试类。

快速通道不默认要求 TDD RED、完整测试、全模块 install、重复 `verify`、预检或全局校验。

### 变更范围识别

默认使用当前工作树相对 `HEAD` 的差异：

```bash
git status --short
git diff --name-only
git ls-files --others --exclude-standard
```

如需统一公共基线，按后续脚本规范增加 `BASE_REF=origin/<upstreamBranch>`；具体分支以 `praxis.projects.toml` 为准。

## P1（重要）

### 后端

```bash
task project -- verify backend <需求名>
task project -- run backend <需求名>
```

- `verify` 使用 Git 变更映射 Maven 模块，并执行最小并行编译。
- `task project -- verify` 不选择或切换 JDK，Maven 直接继承调用进程的全局 `PATH` / `JAVA_HOME`。
- 排查 Maven 运行时必须先执行 `mvn -v`，只以 `Java version:` 和 `runtime:` 字段为准；`OS name` / `version` 是操作系统版本，不是 JDK 版本。
- 没有上述命令证据时，JDK / 注解处理器不兼容只能列为待验证假设，不得改写 `JAVA_HOME`、Maven 或 Lombok 配置。
- 禁止手动执行根级 `mvn ... -am install`；默认使用 `task project -- verify backend <需求名>` 的增量 compile。只有发布本地 Maven 制品或跨仓库联调时才允许 install。
- 仅 SQL 文件变更时，`verify` 不触发 Java/Maven 编译。
- SQL-only 交付说明至少包含 SQL 内容复核、路径命名/Flyway 顺序、是否需人工执行或数据库验证。
- 涉及字段长度、唯一索引、幂等键、任务调度参数时，L1 验证必须补齐边界和幂等场景。
- `run` 为交互脚本，可选择最小编译、构建 `lamp-support/lamp-boot-server` 或启动 jar；全量 install 仅用于发布本地 Maven 制品或跨仓库联调。
- 默认单体启动路径为 `lamp-support/lamp-boot-server/target/lamp-boot-server.jar`。

### Web

```bash
task project -- verify web <需求名>
```

- 先按变更文件定位应用/包。
- 普通源码变更默认只 lint 变更文件，不自动执行包级 `vue-tsc`。
- 构建配置、全局类型或依赖策略变更不得把 eslint 提升为全仓扫描；仍只 lint 需求变更范围内源码文件。
- 只有用户明确要求或设置 `MOM_WEB_PACKAGE_TYPECHECK=1` 时，才执行相关包 `pnpm -F <package> run --if-present typecheck`。
- Web 验证脚本发现目标 worktree 缺 pnpm 依赖时自动先执行 `pnpm install`。

### PDA

```bash
task project -- verify mes-pad <需求名>
task project -- verify mes-pda <需求名>
task project -- verify qms-pad <需求名>
task project -- verify wms-pda <需求名>
```

- PDA 普通源码变更优先 lint 变更文件。
- 普通源码变更优先 lint 变更文件；PDA 项目级 `pnpm type-check` 属于全仓扫描，默认不自动执行。
- 包管理、构建配置、全局类型变更不得把 eslint 提升为全仓扫描；只有用户明确要求或设置 `MOM_PDA_FULL_TYPECHECK=1` 时才执行 `pnpm type-check`。
- PDA 验证脚本发现目标 worktree 缺 pnpm 依赖时自动先执行 `pnpm install`。

### 大屏

```bash
npm run build:dashboard -- <看板名称>
npm run build:report
```

- 大屏目前未统一 verify，按报表或看板最小构建验证。

### 任务执行实践

- 子任务过大先拆“调查”worker，先交付依赖图、风险和推荐拆分。
- 并行子任务要写明收口边界，避免主任务等待不确定串联。
- 调试类任务按假设收敛：先列观察事实，再给最多 2-3 个候选原因，逐个用最小证据排除；禁止直接堆修复。

## P2（优化）

- 收敛验证路径到统一脚本模板，减少每类项目的重复说明。
- 完善跨项目复用的验证矩阵，持续减少 L0/L1/L2 主观判断。
- 逐步建立验证失败后自动补充证据和复测结论的模板。
