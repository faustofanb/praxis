# 入口与自动化

## 目标

统一 Praxis 在 IFC MOM 聚合工作区中的项目分发、脚本入口、平台适配和自动化边界。

## 标准入口

- Codex 平台默认入口：`AGENTS.md`
- Claude 平台默认入口：`.claude/CLAUDE.md`
- 精简索引：`.praxis/extensions/ifc-mom/rules/global/00-工作流精简索引.md`
- 项目映射：`praxis.projects.toml`
- Praxis 通用配置：`.praxis/core.toml`
- 项目适配配置：`.praxis/project-adapter.toml`
- 平台适配配置：`.praxis/platforms/`
- Rule/Skill 模板：`.praxis/templates/`
- 任务分发：`task`（`Taskfile.yml` 编排入口）
- 验证编排：`uv run scripts/codex/verify.py`
- 前端/PDA 辅助分析：`bun run scripts/codex/*.ts`
- 需求文档规范：`.praxis/extensions/ifc-mom/rules/global/05-需求文档组织规范.md`
- 迁移规则：`.praxis/extensions/ifc-mom/rules/projects/backend/07-数据库迁移与Flyway规范.md`
- Code Graph 入口：`task system -- codegraph status|explore|query|impact`
- 过程改进记录：`todo.md`

## 自动化脚本约束

- 只使用 Python(`uv`) 与 TypeScript(`bun`)；不新增 Bash/zsh 自动化入口。
- Python 负责跨项目任务分发、TOML 配置读取、Git/worktree 管理、变更识别、验证编排和后端 Maven 模块识别。
- TypeScript 负责前端、PDA、大屏等 Node 生态相关分析，例如变更文件分类、package 目标识别和前端配置解析。
- Bun 不存在时，应先安装 Bun，再落地或运行 TypeScript 自动化脚本。
- 自动化运行时不替代业务项目命令：后端仍使用 `mvn`，Web/PDA 仍使用 `pnpm`，大屏仍使用 `npm`。
- 自动化脚本按职责拆分模块；入口文件只负责参数解析与分发。
- 配置读取、Git/worktree、文档初始化、上下文输出、交付收口、验证编排不得长期堆叠在单个大文件中。
- Python 关键函数应补充方法级 docstring；TypeScript 关键导出函数或复杂判断处应补充中文说明。
- 复杂判断、兼容分支、性能取舍和风险控制必须在代码附近补充中文注释。

## 根仓库边界

- 根目录 Git 仓库只用于管理工作流文件，例如 `AGENTS.md`、`.praxis/extensions/ifc-mom/rules/`、`.praxis/extensions/ifc-mom/skills/`、`.codex/`、`scripts/codex/`、`todo.md` 和工作区说明。
- 业务子项目仍按各自 Git 仓库管理，根仓库默认不跟踪 `ifc-*`、`LargeVisualizationScreen/`、`docs/` 和 `.worktrees/`。
- 根目录执行 `git status` 只用于检查工作流文件变更；业务代码状态必须进入对应子仓库或需求 worktree 后检查。
- Codeup HTTPS Git 操作优先使用 `task`/`rtk` 工作流入口；必须手工执行底层 Git 时使用 `rtk git ...` 或 `/usr/bin/git ...`，禁止裸 `git ...`。
- 根仓库不得替代业务需求的 worktree、feature 分支、deliver 或 cleanup 流程。

## 统一入口

带参数的分发任务必须使用 `--` 把子命令和参数传给任务分发器，例如 `task req -- index <需求名>`；若写成 `task req index <需求名>`，go-task 会把 `index` 当成独立任务名解析。

```bash
task list
task system -- praxis-profile
task system -- template-check
task project -- status <project>
task project -- verify <project> <需求名>
task project -- run <project> <需求名>
task project -- shell <project> <需求名>
task project -- worktree <project> <任务名>
task req -- init <需求名> <用户原始需求原文>
task req -- iter <需求名> analysis <主题>
task req -- iter <需求名> plan <主题>
task req -- iter <需求名> progress <主题>
task req -- check <需求名>
task req -- index <需求名>
task req -- db-plan <需求名>
task docs -- tolaria-check [<需求名>|--all]
task docs -- tolaria-publish <需求名>|--all
task project -- start <project> <需求名> <用户原始需求原文>
task context -- --brief <project> <需求名>
task context -- <project> <需求名>
task project -- preflight <project> <需求名>
task gate -- ready <project> <需求名>
task gate -- guard <project> <需求名>
task gate -- migration-check <project> <需求名>
task delivery -- finish <project> <需求名>
```

脚本不覆盖当前场景时，才进入需求 worktree 直接执行底层命令；涉及业务代码时不得进入主项目目录开发或启动。
