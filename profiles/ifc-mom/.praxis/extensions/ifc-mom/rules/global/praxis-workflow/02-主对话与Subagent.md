# 主对话与 Subagent

## 默认路径

- 默认由主对话完成需求判断、源码调查、实现、最小验证和结果汇总。
- 只有用户明确要求并行，或主对话无法可靠完成可独立隔离的高风险工作时，才派发 subagent。
- 答疑、确定性维护、单项目小改默认不派发，记录 `subagent: waived-small-change` 和原因即可。
- Tester/Quality、独立复核、额外测试和门禁只能作为选项；得到用户明确许可后才能执行。
- 浏览器、桌面控制、管理页面、登录态、外部联调和发布不属于默认验证范围。

## 角色边界

角色是职责说明，不是必须创建的运行时 Agent：

- Main：需求真相、项目路由、风险决策、写锁、用户确认和最终结论。
- Requirement：需求保真、证据、验收口径和调查清单，默认只读。
- Execution：限定范围内的源码调查、实现和最小验证。
- Quality：经用户许可后的独立复核，默认只读。
- Delivery：经用户许可后的收口准备；提交、推送、交付和清理仍需单独确认。

角色细则只在实际派发对应角色时读取
`.praxis/extensions/ifc-mom/skills/global/mom-agent-workflow/SKILL.md` 及其匹配 reference。

## 派发条件

以下情况可以建议派发，但不能替代用户授权：

- 两个以上项目或互不冲突的独立调查。
- SQL、迁移、权限、异步、公共模块、生产数据或报表口径等高风险工作。
- diff 超过 300 行，或日志超过 120 行且工具无法直接提炼根因。

能由 dbx、LSP、Code Graph、`rg`、源码读取或 `task project -- verify` 给出事实时，优先使用工具。

## 派发契约

每个子任务至少说明：

- `role_agent`、`task_id`、目标和完成条件。
- 可读范围、独占写范围和最小验证命令。
- 必要输入与结构化输出要求。
- `no_nested_agents: true`；需要继续拆分时返回主对话。

同一文件、迁移序列、接口契约或组件只能有一个 writer。提交、最终验证和交付由主对话串行处理。

## 上下文预算

- 主对话默认读取 `task context -- --brief <project> <需求名>`；只有复杂恢复或角色交接才读取完整 context。
- 不向 subagent 复制完整对话、全量规则、源码或长日志。
- subagent 只回传结论、关键证据路径、变更文件、验证摘要和残余风险。
- 需要长期保存的调查结论写入需求目录；没有新增可复用信息时不创建阶段文档。

## 回报状态

- `PLAN`：计划、风险、验证命令和写入范围。
- `CHECKPOINT`：阶段结论或需要主对话决策的事项。
- `RESULT`：完成证据、变更、验证和残余风险。
- `BLOCKED`：具体阻塞和继续所需的最小决策。
