# 调查门禁

## 定位

涉及真实数据、表关系、字段来源、报表口径、SQL、迁移或数据修复时，数据库 MCP 只读调查是源码实现前的前置门禁。当前工作流默认使用 dbx MCP 获取数据库信息，细则按优先级排列。

## P0 — 强制调查

- 改 SQL、迁移、报表口径、数据修复、字段映射、表关系、接口数据口径：**必须先**通过 dbx MCP 做数据库只读调查。
- 使用 dbx 前先读取当前 workspace 的 `praxis.projects.toml`，按 `[database.local]` 确认本地 `connection`、`database` 和 `schema`；同一个 `LOCAL` 连接可能同时包含 mom/aotu 等多个本地库，禁止只凭连接名推断数据库。
- 使用 dbx 先执行 `dbx_list_connections` 确认连接；本地查询必须命中 `[database.local].database`，默认只查 `LOCAL` / `DEV`，`PRO` 或疑似生产库必须先获得用户明确许可。
- **禁止**未经许可查询生产库或疑似生产数据；须先确认环境、范围、条件和风险。
- 生产数采/日志/流水/历史明细大表：**禁止**全表扫描与无条件查询；须按时间、设备、产线、主键或业务单号限定范围。
- 无法连接数据库时，不得把猜测写成已确认结论；须标注“未连接数据库，待人工确认”。

## P1 — 分级与查询规则

| 级别 | 场景 | 动作 |
|------|------|------|
| 强制 | 见 P0 | 必须查库 |
| 风险提示 | 字典、主数据、统计展示等不直接改口径 | `preflight` 标记 `optional-risk`，说明是否查库 |
| 可豁免 | 纯代码解释、静态文案、单文件低风险修改 | 交付说明写明豁免原因 |

查询约束：

- 默认只读；优先使用当前可用的 `dbx_list_connections`、`dbx_list_tables`、`dbx_execute_query`；需要在 DBX UI 中展示结果时才使用 `dbx_execute_and_show`；除非用户明确确认，不执行写入/删除/DDL。
- 每次业务查询前先通过 `select current_database(), current_schema();` 或等价只读查询确认当前库和 schema。
- 需要字段、索引、约束、注释或视图定义细节时，通过 `dbx_execute_query` 查询 `information_schema`、`pg_catalog` 或 PostgreSQL 元数据函数，不调用未暴露的 dbx 工具名；`information_schema` 查询必须限定 `table_catalog = [database.local].database` 和 `table_schema = [database.local].schema`。
- 样例查询须 `limit`/分页，避免 `select *`、无条件 `count(*)`。
- 先查表结构、约束/索引、字典主数据、样例与分布，再写代码或 SQL。
- Code Graph、源码、历史文档仅作定位；数据口径结论须回到真实库或标注待确认。

## P2 — 落盘要求

调查结论写入 `01-需求分析拆解/` 或 `04-产出物/关联信息调查/`，至少包含：

- dbx 连接名、数据库名、schema、查询环境、关键 SQL/对象
- 已确认表关系与字段口径
- 字典/主数据/样例特征
- 未决问题与是否需人工复核

## 迁移中间产物（P0）

涉及迁移脚本、DDL、菜单授权、低代码模型或 MagicAPI 迁移 SQL：

- 开发/调查阶段只写需求目录中间产物（新需求用 `04-产出物/SQL/`）。
- 正式 Flyway 目录仅在收尾、中间产物确认并完成差异复核后写入。
