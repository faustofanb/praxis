# core

`@praxis/core` 当前实现行为。模块定位、依赖方向等架构事实的唯一权威是 `docs/02-system-design.md` §4.2；事件契约形状见 ADR-0009。

## 当前内容（M1-T002 起）

入口唯一：`src/index.ts`。只依赖 `@praxis/contracts`；无 I/O、无时钟、无随机、无环境变量。

- **StateReducer**（`src/state/reducer.ts`）：`reduceSession(state, event) -> nextState` 纯函数，覆盖 Session/Turn、工具执行、模型调用与 Goal/Epistemic 事件切片。docs/02 §7 的 DerivedSessionState 全部投影（goal/observations/hypotheses/plans/challenges/lastVerification）自 M4-T001 起落地。
  - `SessionStatus`：`EMPTY | ACTIVE | PAUSED | COMPLETED`；`initialSessionState()` 给出 EMPTY 初态（headSeq 0）。
  - 派生态字段：`sessionId`（由 SessionCreated 绑定）、`headSeq`、`currentTurnId`、`turnIds`（全部出现过的 turn，防复用）、`toolExecutions`（M2-T003 起，`ReadonlyMap<ToolExecutionId, ToolExecutionSnapshot>`，快照含 turnId/name/argumentsJson/effect/status 及终态事实字段 resultJson/rejectionReason/failureMessage/indeterminateReason）、`pendingModelRequest`（M2-T004 起，`{model}`，由 ModelRequestStarted 设置、ResponseCompleted/Failed 清除）、epistemic 投影（M4-T001 起，ADR-0012）：`goal`（GoalSet latest-wins）、`observations`/`hypotheses`/`plans`/`challenges` 注册表 map + `activePlan` 便捷视图 + `openChallenges` 投影、`lastVerification`（latest-wins）。
  - 迁移合法性（fail-closed，抛 `IllegalTransitionError`）：EMPTY 只接受 SessionCreated；Resumed 仅自 PAUSED；Paused/Completed 仅自 ACTIVE 且无未闭合 turn；TurnStarted 仅自 ACTIVE、无未闭合 turn、turnId 未用过；TurnCompleted 必须闭合当前 turn、turnId 一致、无 pending 模型请求、且当前 turn 无 PROPOSED/AUTHORIZED/EXECUTING 中的工具执行。SessionCompleted 另受 M4-T004 完成阻断法则（docs/02 §14）：存在 `targetType === "completion"` 的 open challenge 即拒绝，error detail 列出全部阻断者 id——v1 policy 即法则本身（无 policy 对象、不咨询模型）；hypothesis/plan/policy 目标不阻断；任何 ChallengeResolved outcome 解除阻断。
  - 工具生命周期（docs/02 §8.2）：ToolProposed 需 ACTIVE+open turn 且无 pending 模型请求，toolExecutionId 单用并归属当前 turn；Authorized 仅自 PROPOSED；Rejected 自 PROPOSED（或 AUTHORIZED——仅崩溃恢复放弃：授权未开始可证明未执行，是诚实拒绝而非强转失败）；Started 仅自 AUTHORIZED；三个终态仅自 EXECUTING，终态不可复活；跨 turn 的工具事件拒绝。M3-T001 起 ToolReconciled 仅自 INDETERMINATE（ADR-0011）：`succeeded`/`failed` 落为终态（与执行终态同样不可复活）、`indeterminate` 保持 INDETERMINATE 并更新 reason，未定论前可多次 reconcile；快照新增 `reconciliationCount`（ToolProposed 起 0，每次 reconcile +1）。M3-T004 起 ToolReconciled 是历史事实：只要求 ACTIVE 会话与 INDETERMINATE 执行，不要求 open turn（§17 升级会先闭合 turn 再 SessionPaused，resume 后的会话无 open turn 也必须能落定事实——否则人工解锁环在结构上不可能）；PAUSED 会话仍拒绝（resume 是唯一解锁）。
  - 模型生命周期（M2-T004）：三个模型事件均需 ACTIVE+open turn；Started 要求无 pending，ResponseCompleted/Failed 要求有 pending（请求-响应严格交替，单写者顺序由 reducer 保证）。
  - Epistemic 法则（M4-T001 起；docs/02 §5/§13–14、ADR-0012）：九类事件均需 ACTIVE 会话、均不要求 open turn（§16 的 host/extension 贡献通道——session 级事实而非 turn 动作，与 ToolReconciled 历史事实同一先例；PAUSED 拒绝，resume 是唯一解锁）。id 注册表法则：observation/hypothesis/plan/challenge id 单用；HypothesisStatusChanged 的 from-status 由重放推导、`proposed→{supported,falsified,superseded}`、`supported→{falsified,superseded}`、falsified/superseded 终态，证据按方向归档（→supported 入 support、→falsified 入 conflicts、supersession 只带 reason）；PlanSet 引用的 hypothesis 必须已存在（fail-closed），新 PlanSet 自动把旧 active plan 置 superseded；PlanInvalidated 仅作用于 active plan（终态）；ChallengeRaised 的 hypothesis/plan 目标经注册表校验（completion/policy 自由字符串），ChallengeResolved 仅自 open、outcome 落为终态并移出 openChallenges；VerificationRecorded latest-wins，`inconclusive` 一等不强转。证伪是事实、失效是决定——reducer 绝不因 hypothesis 被证伪而自动失效引用它的 plan（M4-T003 的编排策略拥有该决定权；epistemic-v1 fixture 的 seq 20 检查点钉死此边界）。
  - 流连续性兜底：事件 seq 必须恰为 headSeq+1（防间隙/重放），事件 sessionId 必须与流一致。这是对 store 契约的廉价防御性复核。
  - `foldSessionEvents(events)`：全流重放辅助，recovery/projection 共用。
- **Tool Runtime 执行器**（`src/tools/tool-runtime.ts`，M2-T003 起）：`executeToolCall(deps, proposal, {signal, authorizer?})`——先经 port 折叠当前状态（要求 ACTIVE + open turn，否则拒绝执行），再按序追加 ToolProposed →（校验/授权）→ ToolAuthorized|ToolRejected → ToolStarted → 终态事件。proposal 可带 `toolCallId`（M2-T004 起）写入 ToolProposed 关联模型调用。时钟与 ID 源注入（Core 无环境时间/随机）；未注册工具按最保守 effect 类提案后显式拒绝；参数不合 schema 在授权前拒绝；`ToolAuthorizer` 判别输入自 M3-T002 起含 `requiredCapability`（来自工具注册元数据，模型提案无法影响）；`readOnlyAuthorizer` 为 v1 默认 deny-by-default 策略（M3 capability 的接缝，`capabilityAuthorizer` 为其上替代实现）。执行器崩溃分支遵守 §8.2：read_only → FAILED，否则 INDETERMINATE（绝不把未知强转为失败）。`projectSessionState(deps)` 经 port 折叠派生态。M6-T001 起 options 可选 `extensions` host：authorizer 批准后咨询 beforeTool（deny-only；authorizer 拒绝时根本不咨询——扩展只收紧永不放宽，ADR-0007 顺序不变），每个终态 settle 时触发 afterTool。
- **效果类契约执行**（`src/tools/effect-policy.ts`，M3-T001 起；ADR-0006/0011）：`retryPolicyForEffect(effect)` 全函数表——read_only/idempotent_write→`safe_to_repeat`、reconcilable_write→`repeat_only_after_reconciled_absence`、non_idempotent_write→`never_repeat`；`validateToolDefinitions(tools)` 注册校验（reconcilable_write 缺 reconcile、重名、M3-T002 起写效果工具缺 `requiredCapability` 即抛错——ADR-0007），由 `runTurn` 在任何执行前 fail-closed 调用（直接调 `executeToolCall` 的测试不经此校验）。谁在恢复时调用 reconcile、何时升级，归 M3-T004 的恢复编排。
- **Capability 策略**（`src/capability/policy.ts` + `src/capability/authorizer.ts`，M3-T002 起；docs/02 §9、ADR-0007）：`capabilityDecision(requirement, config, now)` 纯决策表——无 I/O、时钟注入、输入只有 host 提供的 grants/leases（模型可从 `capabilityPolicySummary` 得知所拥有能力，但永远无法授予权限）。fail-closed 判序：① 请求 scope 逃逸出全部 `workspaceRoots` → deny（先于一切 grant，全局 grant 也不能带出 workspace）；② 匹配 grant → allow（via grant）；③ 未过期 lease → allow（via lease 并记 leaseId，供拒绝/审批引用证据）；④ 匹配但已过期 lease → 无条件 deny（docs/02 §9.2：过期即拒，`now === expiresAt` 已过期，无宽限）；⑤ approvable 能力 → requires_approval（携 ApprovalRequest）；⑥ 其余 → deny。`capabilityPolicySummary(config, now)` 确定性投影——grants 排序列出、lease 标注 `expires N`/`EXPIRED`、approvable 明示"re-proposing does not grant them"。`capabilityAuthorizer({policy, now})` 把决策表适配到 ToolAuthorizer 接缝（§9.3 第 1 层；第 2 层路径/root 限制在工具实现，M3-T003）：requires_approval 直接 rejected fail-closed（审批 UX 是扩展，缺位不得开门）；写效果工具无 requiredCapability 到达运行时 → rejected（注册校验之外的纵深防御）。
- **Agent Loop**（`src/agent-loop/`，M2-T004 起；docs/02 §10–12、§16–17）：
  - `conversation.ts`：`projectConversation(events)` 纯投影——TurnStarted.input→user 消息、ModelResponseCompleted→assistant 消息、工具终态事件→tool 消息（succeeded 直引 resultJson，rejected/failed/indeterminate 以 `{status, reason|message}` JSON 记述；未关联 toolCallId 的执行回落到 toolExecutionId）。M3-T001 起 ToolReconciled 作为追加的 tool 事实投影（`{status: outcome, reconciled: true, result|message|reason}`）——模型看到定论事实，但早先的 indeterminate 消息保留，历史不被改写。重放安全：不解析参数、不重执行工具、结果作为不透明事实入上下文。
  - `append-event.ts`（M3-T004 起自 run-turn 提取）：`appendEvent(deps, init)` 单写者追加——从头折叠取 headSeq、`seq = head+1`、`append(..., expectedHead)`、再全量重折叠返回派生态；`eventEnvelope(deps)` 统一事件外壳（actor 缺省 system）。agent loop 与恢复编排共用，派生态永不本地拼装。
  - `recovery.ts`（M3-T004 起；docs/02 §17 步骤 6–7、ADR-0011）：`reconcileIndeterminateExecutions(deps, {signal})`——按插入序遍历全部 INDETERMINATE 执行：工具未注册或未定义 reconcile → unresolved（不落事实）；recorded input 解析（JSON.parse + 工具 inputSchema）失败 → 落 ToolReconciled `indeterminate`（"recorded input no longer parses"）并 unresolved；否则调用工具的 verification-only `reconcile`（抛错同样落诚实 indeterminate 事实"reconcile attempt failed"，绝不猜），结论按 succeeded/failed/indeterminate 落 ToolReconciled，前两者入 `settled`、后者入 `unresolved`。返回 `ReconciliationReport {settled, unresolved}`；全程不调用 execute——验证不是重放。`pauseForUnresolvedIndeterminates(deps, unresolved)`——空则 no-op；否则先 TurnCompleted（若有 open turn）再 SessionPaused（payload {}）。
  - `plan-invalidation.ts`（M4-T003 起；ADR-0012 把该决定保留给运行时）：`invalidatePlansFalsifiedByHypotheses(deps)`——折叠状态后按登记表插入序遍历 active plan，凡 hypothesisId 指向 falsified/superseded 假设即落一条 PlanInvalidated（reason 引用假设 id 与状态，事实自释；system actor），无匹配则零追加（幂等，重放确定）；不咨询模型——新计划由模型自己的 PlanSet 到来。返回 `{invalidated, active}`。
  - `run-turn.ts`：`runTurn(deps, {input?}, {signal, guards?, authorizer?, budget?})`——入口要求 ACTIVE（PAUSED 会话直接拒绝：SessionResumed 是唯一解锁）。随后诚实崩溃恢复：悬挂 EXECUTING→ToolIndeterminate（"outcome unknown"）、悬挂 PROPOSED/AUTHORIZED→ToolRejected（明确"never executed"）、悬挂 pendingModelRequest→ModelRequestFailed（kind unknown）；绝不假设未执行、绝不重放历史工具。M4-T003 起崩溃恢复后先跑 invalidatePlansFalsifiedByHypotheses（证伪→失效的运行时决定，见 plan-invalidation.ts；不匹配即零追加）。M3-T004 起紧接 §17 步骤 6–7：运行 reconcileIndeterminateExecutions，unresolved 非空则 pauseForUnresolvedIndeterminates 后返回 `{kind: "paused", reason}`（升级为 durable 会话状态，模型不被咨询——不得带着未定论的外部效果继续 turn）；全部落定或本无未定论则照常续跑。之后循环：projectConversation → buildContext → ModelRequestStarted → 消费流 → ResponseCompleted（工具调用则逐个 executeToolCall 并继续；纯文本则 TurnCompleted 收口）/ providerError 记 ModelRequestFailed（可重试在同 turn 内重试）/ 静默结束（取消）记 ModelRequestFailed 并返回 cancelled。
  - 守卫 `TurnGuards`（maxStepsPerTurn=16、maxConsecutiveModelFailures=3，`validateTurnGuards` fail-closed）：确定性预算按每次 runTurn 计——暂停后重入即恢复（同一 open turn 续跑，无新 TurnStarted）。超限返回 `paused`（turn 保持 open，Session 状态不变——reducer 禁止带 open turn 的 SessionPaused，这是记录在案的 v0 偏差：预算暂停是进程内结果而非会话状态迁移；与 §17 升级暂停的 durable 语义不同，后者闭 turn + PAUSED 状态 + 人工 resume 才能解锁）。open turn 时传 input 拒绝；无 open turn 时缺 input 拒绝；工具 parametersJson 非合法 JSON 在任何事件追加前拒绝。
- **ContextBuilder v0**（`src/context/`，M2-T002 起；设计见 docs/02 §12、docs/03 M2.2）：
  - `budget.ts`：`ContextBudget` 六项硬上限（maxRecentMessages / maxFragmentBytes / maxToolResultBytes / maxActiveObservations / maxActiveHypotheses / maxEstimatedTokens）+ `DEFAULT_CONTEXT_BUDGET`（maxActiveObservations=8、maxActiveHypotheses=8）；`validateContextBudget` fail-closed（正整数、字节上限 ≥ 40 以容纳截断标记）。maxActiveHypotheses 为 M5-T001 新增。
  - `builder.ts`：`buildContext(input, budget?)` 纯投影——system 片段恒为第一条（history 内出现 system 消息即 `InvalidContextError`），可选 `epistemicBrief` 以空行拼进 systemPrompt 之后组成**单一** system 片段（M4-T002；undefined 时逐字节等同旧投影），history 取最新窗口、按片段截断（保头 + `…[+N bytes truncated]` 标记，UTF-8 字节感知），超出 token 估计上限（全部字符串字段的字节和 / 4 向上取整）时自最旧丢弃；尾消息不可丢弃，system+尾消息仍超限则抛 `ContextBudgetExceededError`。M5-T001 起：带 brief 的组合 system 片段超过 `maxFragmentBytes` 时同样抛 `ContextBudgetExceededError`（静默尾截断可能吃掉不可压缩分节）；无 brief 时超长 prompt 仍按 v0 头截断。M5-T002 起：窗口/token 循环做收敛迭代——每轮按当前窗口计算 recap 并组合 system 片段，仍超限则再丢一条并重算；丢弃数 > 0 时在片段末尾（brief 之后）追加 `## Compacted history` 单行按角色计数 recap（计数只来自被丢弃消息，无时钟/随机/模型文本），丢弃数为 0 时输出与 M5-T001 逐字节一致；recap 属 system 片段而非合成 history 消息，且计入 fail-closed 组合界。返回带 estimate（totalBytes/estimatedTokens/droppedMessages/truncatedFragments）。M6-T001 起可选 `extensionFragments`：渲染为 brief 之后的 `## Extension: <source>` 节（source 由 host 盖章），单节可截断（compactable）、组合后超限与 oversize brief 同法 fail closed——扩展文本永不挤占不可压缩分节。
  - `epistemic-brief.ts`（M4-T002，docs/02 §12.4；M5-T001 双层法则）：`projectEpistemicBrief(state, budget)` 纯渲染器——不可压缩层 goal+constraints → active plan（falsifiedIf/hypothesis 引用）→ open challenges → pending INDETERMINATE → latest verification（inconclusive 原样）逐行渲染、永不因字节压力让位；可压缩层 active hypotheses（仅 proposed/supported，最新 maxActiveHypotheses 条 + `…[+K older active hypotheses omitted]`）与 observations（最新 maxActiveObservations 条）整节让位并附 `…[+K brief lines omitted]` 诚实计数；brief 总字节 ≤ maxFragmentBytes；不可压缩层自身放不下即抛 `ContextBudgetExceededError`。M4-T004 起存在 completion-target open challenge 时追加 `## Completion blocked` 分节（逐条列出阻断者）。认识论切片全空返回 undefined。推论：需要单行截断的病态行约占满整个 cap，其分节必然让位（可压缩）或 fail closed（不可压缩）。
  - 截断后的 assistant 工具参数仅作上下文展示——可执行工具状态在事件库中，绝不从 context 反解。v1 无检索、无摘要（§12.3 明确后置）。
  - `run-turn.ts`（M4-T002 起）：每步重折流并经 projectEpistemicBrief 重建 brief 传入 buildContext——turn 中途落地的认识论事实下一步即到达模型；M5-T001 起不可压缩层放不下时 turn 在任何 ModelRequestStarted 之前 fail closed（签名未变，loop 零改动继承法则）。

- **Extension Host 与接缝**（`src/extensions/host.ts`，M6-T001 起；docs/02 §19、ADR-0013）：`createExtensionHost()` 实例工厂——全部状态在闭包内（无模块级全局；卸载/丢弃 host 即无残留）。`register` 先 `validatePraxisExtension` 再查重（`DuplicateExtensionError`）；`unload(name)` 立即生效。注册顺序即每个 hook 的调用顺序；`beforeTool` 首个 deny 生效并返回 `{extensionName, decision}`；`contributeContext` 按序收集片段并**亲自盖章 source 为扩展自己的名字**（防冒名）。每 hook 调用按该扩展的 `failurePolicy`：`isolate`（默认）吞错零贡献；`fail_closed` 包装为 `ExtensionHookError`（含扩展名与 hook 名）重抛——骑 §17 既有崩溃恢复，无第二条失败路径。返回形状违规（非数组 fragments / 非 deny 决策）无视策略直接抛 `InvalidExtensionError`（契约违规，非偶发失败）。`observeEventStore(store, host)` 装饰器：append 成功后逐事件触发 onEvent（只读；open turn 由 TurnStarted/TurnCompleted 事实推导，无 store 读），readStream 原样透传；fail_closed 的 onEvent 从 append 重抛但 append 本身已持久化。接缝调用点（一次性全部落入 Core，此后 T002/T003 不再改 Core）：runTurn——TurnStarted 追加后 onTurnStart（仅开 turn 的那次调用，重入不重触发）、每步 contributeContext（产物进 buildContext 的 extensionFragments）、model.complete 两侧 beforeModel/afterModel（result 为 completed|providerError|endedSilently 规范视图）、经 observing-store 的 onEvent、每个 TurnOutcome 路径 onTurnEnd（崩溃路径除外——诚实留给恢复）；executeToolCall——authorizer 批准后、ToolAuthorized 前咨询 beforeTool（deny → 显式 ToolRejected，reason 引用扩展名，绝不执行），每个终态（含 REJECTED）触发 afterTool。零扩展恒等：无 host/空 host 时事件流与模型请求逐字节不变（既有 428 测试未改一行通过是证据）。
