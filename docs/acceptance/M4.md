## Scenario Acceptance

- [x] hypothesis falsification invalidates old plan
  - 命令：`bunx vitest run tests/plan-invalidation.test.ts tests/integration/epistemic-context.integration.test.ts`
  - 证据：轮次入口 `invalidatePlansFalsifiedByHypotheses` 对 hypothesis 已 falsified/superseded 的 active plan 追加 `PlanInvalidated`（自解释 reason）；pass 幂等、重放确定、显式作废先于 pass 时保持沉默（`tests/plan-invalidation.test.ts` 7 项）。集成层：证伪发生在 turn entry，模型随后的 brief 中不出现 `## Active plan`（"a falsified hypothesis invalidates its plan at turn entry, so the model sees no active plan"）。reducer 法则：invalidation 标记计划 terminal 并清空 `activePlan`（`tests/reducer-epistemic.test.ts` plan law）。
- [x] challenge changes next legal action
  - 命令：`bunx vitest run tests/reducer-epistemic.test.ts tests/context-epistemic.test.ts tests/integration/epistemic-context.integration.test.ts`
  - 证据：open 的 completion-target challenge 使 `SessionCompleted` 抛 `IllegalTransitionError`（reducer 转移法则，错误信息列出全部未决 challenge id）；任一 `ChallengeResolved` outcome 解除阻断；非 completion 目标不单独阻断；多个 completion challenge 需全部解决（`tests/reducer-epistemic.test.ts` challenge law 4 项）。brief 同步渲染 `## Completion blocked` 直至解除（"renders the completion block while a completion-target challenge is open, and stops once resolved"）。集成层：completion-target challenge 改变会话路径——完成被拒直到 resolved（epistemic-context 集成套件）。

## Failure Acceptance

- [x] challenge cannot be only a log entry
  - 命令：`bunx vitest run tests/reducer-epistemic.test.ts tests/context-epistemic.test.ts`
  - 证据：阻断不在日志/提示层——它在 reducer `SessionCompleted` 转移法则内，未决 completion challenge 存在时状态机拒绝转移；challenge 开闭本身由 durable 事件（`ChallengeRaised`/`ChallengeResolved`）折叠而来，无法绕过事件流伪造"已解决"。brief 的 `## Completion blocked` 只是把同一事实投影给模型，不是唯一的执行点。
- [x] falsified plan cannot keep executing
  - 命令：`bunx vitest run tests/plan-invalidation.test.ts tests/context-epistemic.test.ts tests/reducer-epistemic.test.ts`
  - 证据：falsified/superseded hypothesis 状态 terminal（不可复活）；其计划经 durable `PlanInvalidated` 作废、`activePlan` 清空；brief 法则使作废计划不再渲染（模型每轮看到的计划分区为空，作废步骤不再被提供）。执行不依赖模型自觉：作废发生在 turn entry 投影，而非请求模型"请忽略旧计划"。

## Design–Implementation Consistency (docs/07 §6)

- 新增 package？无。M4 全部在既有 contracts/core/testkit 内完成；`evals/` 是目录不是包（无 package.json，不进 workspace 依赖图）。
- 新增 Core dependency？无新包依赖；core 新增内部模块（认识论投影/失效 pass/挑战法则）。新增 durable contract（九个认识论事件）有 ADR-0012。
- 新增 durable contract？是——GoalSet/ObservationRecorded/HypothesisProposed/HypothesisStatusChanged/PlanSet/PlanInvalidated/ChallengeRaised/ChallengeResolved/VerificationRecorded（ADR-0012）。纯增量事件：旧流不可能含新事件，既有 replay fixture 原样通过（`test:replay` 16/16 @ 基线）；重放确定性由 "folding the stream twice yields identical states" 与 plan-invalidation replay 测试钉死。
- optional extension 承担 Core invariant？否——失效 pass 与完成阻断都在 core（reducer/turn entry）；eval 套件只产证据不执法（non-core-gating，不进任何 check 链）；testkit 仅 dev 依赖。
- 两个事实源/两个状态管理器？否——认识论状态是事件流的 reducer 投影；brief 是该状态的有界投影（context 是工作状态，不是第二事实库）。
- 过期未更新的系统设计？无——docs/02 §14、docs/03 M4 清单、`docs/subsystems/contracts.md`、`docs/subsystems/core.md` 随各任务同批更新；docs/08 §3 与 `docs/subsystems/testkit.md` 随 T005 更新。
